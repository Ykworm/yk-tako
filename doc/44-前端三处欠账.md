## 0. 为什么现在补这三处

后端三件事都已经能跑，页面上却没有入口。用户必须 curl 才能完成日常操作——功能等于不存在。

**故事一（项目找不到、删不掉）：** 用户在「验收项目」里跟 agent 做了两天活，想再建一个项目分开做。后端 `POST /api/workspaces` 一早就能建，但页面上没有项目列表；他只能在终端里建，建完也看不到。项目越积越多，想删掉没用的那个，同样只能 curl。更糟的是，当前页面永远把新对话送进**默认项目**——用户建的项目如果没有 API 调用带 `workspaceId`，就永远没有对话落在里面。

**故事二（删除没有入口，也没有刹车）：** 用户想删掉一场跑废的会话，页面上只有「新对话」，没有删除。`DELETE /api/sessions/:id` 和 `DELETE /api/workspaces/:id` 都在，但删除是不可逆动作，直接放一个裸按钮会误删；后端已经用 409 挡住「有活 run」和「默认项目」，页面需要把这条拒绝理由原样呈现给用户，而不是自己猜。

**故事三（子代理跑完就消失）：** researcher 子代理跑了十几分钟，折叠成三行摘要回到主对话。用户想追问「那个对比表的数据源是哪几个？」，页面上看不到子代理实例，也不知道它的 `sa_id`。后端已经在 `.tako/subagents/` 里持久化了 wire，`GET /api/sessions/:id/subagents` 能列出实例，`resume_subagent` 工具能接着完整档案继续跑；但用户没有任何入口把这两端接起来。

三件事的共同点：**后端都有契约、前端都没有入口**。所以合成一个前端 loop，一次把页面骨架、确认交互和会话内面板补齐。

## 1. 现状（代码事实，2026-10-23 实读）

### 1.1 后端已有契约（不改）

| 动作 | 端点 | 成功体 | 失败语义 |
|---|---|---|---|
| 我的项目列表 | `GET /api/workspaces` | `{"code":0,"message":"","data":{"workspaces":[{id,name,createdAt,visibility,owner}]}}` | — |
| 建项目 | `POST /api/workspaces` | 201 `{data:{workspace}}` | 400 `114003`「请填写项目名称」 |
| 改名 | `PATCH /api/workspaces/:id` | 200 `{data:{workspace}}` | 404 `114001`；400 `114003` |
| 删项目 | `DELETE /api/workspaces/:id` | 200 `{data:{status:"deleted"}}` | 409 `114005` 默认项目 / 409 `114006` 有活 run；404 `114001` |
| 项目下会话 | `GET /api/sessions?workspaceId=<wid>` | `{data:{sessions:[{id,title,visibility,owner,createdAt,workspaceId}]}}` | 404 `114001` |
| 删会话 | `DELETE /api/sessions/:id` | 200 `{data:{status:"deleted"}}` | 409 `114007` 有活 run；404 `112001`；403 `111204` |
| 子代理档案 | `GET /api/sessions/:id/subagents` | `{data:{subagents:[{saId,agentName,status,createdAt,finishedAt?}]}}` | 404 `112001` |
| 在项目里开新对话 | `POST /api/runs` 带 `workspaceId` | `{sessionId,runId,messageId}` | 404 `114001`（项目看不见） |

字段真身以 `product_api.go` 的 `workspaceBody`、`server.go` 的 `sessionListItem`、`subagent_wire.go` 的 `subagentListItem` 为准。`status` 只有 `complete` / `interrupted` 两值：有 terminal 行是 `complete`，没有是 `interrupted`。

### 1.2 前端现状

- `App.vue` 只有 `chat` / `agents` / `team` 三页（`sessionStorage` 记 `tako.page`），没有项目页。
- 对话页是**单会话**形态：浏览器按租户记住一个 `tako.sessionId.<tid>`，没有会话列表。
- `POST /api/runs` 从未带过 `workspaceId`；服务端于是每场新对话都挂默认项目。用户建的项目没有入口被使用。
- 页面上没有任何删除按钮，也没有 `ConfirmDialog`。
- 子代理 wire 只在磁盘上；页面没有列表，也没有把 `sa_id` 带进对话的入口。

### 1.3 子代理 resume 的真身

`resume_subagent` 是**模型侧工具**（`resume_subagent.go`），不是 HTTP 端点。它的参数是 `{id?, agent?, instruction}`，只认有 terminal 行的完整档案；产出是一个新实例（`resumed_from` 指回原 `sa_id`）。

所以页面上的「继续」**不能直接调用工具**。可选的两条路：

1. 新增一个 `POST /api/sessions/:id/subagents/:saId/resume`，在服务端起一场 run、注入 instruction、把新实例结果写回会话；
2. 页面把「继续这个实例」的请求**填进当前对话的输入框**，用户按 Enter 后由父 agent 调 `resume_subagent`。

选 2（§2.4）：resume 本来就是 agent 对话的一部分，父 agent 需要看到用户为什么要继续、继续做什么；直接起一场旁路 run 会绕开父对话的上下文，还要新造一套「子代理结果如何写回父会话」的契约。页面只做「把意图说清楚」这一步，执行仍走已有的工具链。

## 2. 已拍的页面裁量

### 2.1 「项目」页

导航新增第四页「项目」。页面是**个人项目**的管理面（doc/42：项目只有属主可见），内容：

- 项目列表（`GET /api/workspaces`，按服务端顺序：`created_at,id` 升序）。
- 每个项目一行：名称、创建时间、操作（开新对话 / 重命名 / 删除）。
- 「查看对话」展开该项目下的会话（`GET /api/sessions?workspaceId=`）；每场会话可以「打开」或「删除」。
- 顶部写明「新对话落点」：当前选中的项目名；没选时是「默认项目」。

**为什么把会话挂在项目下：** 项目的价值是「多场对话共用文件」，用户要能看见「这个项目里有哪些对话」。会话列表按需加载（展开才请求），页面首屏只打一次 `GET /api/workspaces`。

### 2.2 当前项目（新对话落点）

- 浏览器按租户记住 `tako.workspaceId.<tid>`；不存服务端（doc/35 原话：当前看哪个项目由前端记住，服务端不保存「我正在看哪个项目」）。
- 项目页顶部的「回到默认项目」**只改新对话落点**，不清当前会话（当前对话继续沿用它自己的项目）。
- 项目行的「开新对话」：把这个项目写成当前项目 → 清掉当前会话 → 回对话页并聚焦输入框。
- 新对话 `POST /api/runs` 只在**没有 sessionId** 时带 `workspaceId`。已有会话不带：服务端本来就不会改已有会话的项目，带了反而会让一个已被删除的项目 id 把已有会话的投递也挡在项目预检上。
- 打开一场已有会话时，若它挂在某个项目上，把当前项目跟着切过去；后续「新对话」自然落在同一个项目。

### 2.3 删除与确认弹窗

- 项目删除：确认弹窗写明「项目里的 N 场对话会一起删除，项目目录里的文件会清掉」。确认前先把该项目的会话列表拉一次，拿到 `sessionIds`，用于事后判断当前会话是否被连带删除。
- 单场删除：确认弹窗写明「只删会话档案；项目目录里的产出文件不受影响」。
- 确认弹窗是独立的 `ConfirmDialog`（遮罩 + `role="dialog"` + Escape 取消 + 焦点落在取消按钮），不沿用 MembersView 的两段式按钮——删除项目和删除会话都是不可逆动作，需要把后果完整写出来，而不是一个「确认删除」小按钮。
- 服务端拒绝（默认项目 409 `114005`、有活 run 409 `114006/114007`）不自己猜，直接把信封 `message` 显示在弹窗里；弹窗保持打开，用户可以去停 run 或换项目。
- 删除成功后：项目从列表移除；若它是当前项目，当前项目清空（回到默认项目）；若当前会话在 `sessionIds` 里，清空对话页。单场删除成功后同理，只清被删的那一场。

### 2.4 子代理列表与「继续」

- 位置：对话页 `.thread` 顶部一条可展开的「子代理 N」条。只对**已有 sessionId** 的对话显示；新对话还没落会话时没有档案可列。
- 数据：`GET /api/sessions/:id/subagents`。会话切换、展开面板、以及一轮 run 结束时刷新。
- 每行：规格名、`sa_id`、状态（已完成 / 未完成）、创建时间。`complete` 才给「继续」；`interrupted` 是崩溃/中断留下的半成品，不给按钮。
- 「继续」的动作：把下面这句话**追加**到输入框并聚焦（不覆盖用户已经写的内容，也不自动发送）：

  ```text
  请用 resume_subagent 继续子代理 sa_xxx（researcher）：接着它刚才的任务继续做下去，完成后把结果告诉我。
  ```

  用户按 Enter 后，父 agent 在正常对话里调用 `resume_subagent({id:"sa_xxx", instruction:"…"})`。`sa_id` 由页面带进上下文，不靠用户记。

**为什么不做直接 resume 端点：** 见 §1.3。resume 的 instruction 是对话语义的一部分；页面替用户写好意图、让父 agent 执行，才不会出现「页面起了一场 run，结果却不知道怎么回写父对话」的第二套生命周期。这个选择也保持了 doc/39「resume 入口是模型侧工具」的裁定。

## 3. 三条端到端链路

**项目 → 新对话：**
用户点项目页「开新对话」→ `localStorage['tako.workspaceId.<tid>'] = ws_x` + `newSession()` → 回对话页发消息 → `POST /api/runs {messageId,text,workspaceId:"ws_x"}` → 服务端 `EnsureDefaultWorkspace` 不走，直接用 `ws_x` 建会话 → `sessions.workspace_id = ws_x` → worker 以 `tenants/<tid>/workspaces/ws_x/` 为作业根 → agent 的产出落项目目录。

**删除项目：**
用户点「删除」→ 前端先 `GET /api/sessions?workspaceId=ws_x` 拿 `sessionIds` → 弹窗写出「N 场对话一起删」→ 确认 → `DELETE /api/workspaces/ws_x` → 服务端事务里软删项目与挂载会话、提交后删项目目录和各会话目录 → 前端移除项目；若 `ws_x` 是当前项目则清空当前项目；若当前会话在 `sessionIds` 里则清空对话页。

**子代理继续：**
子代理跑完 → wire 末行 terminal → `GET /api/sessions/:id/subagents` 列出 `complete` 实例 → 用户点「继续」→ 输入框出现带 `sa_id` 的指令 → 用户发送 → 父 agent 调 `resume_subagent` → 引擎按档案重建子代理、产出新 `sa_id`、`resumed_from` 指回旧实例 → 新 wire 落盘 → 下一轮列表刷新看到新实例。

### 4.2 接口字节（curl，活引擎）

用 dev 账号登录后：

```bash
curl -sS http://127.0.0.1:8901/api/workspaces -H "Authorization: Bearer $AT"
```

→ `code:0`，`workspaces[]` 每项含 `id/name/createdAt/visibility/owner`；空列表是 `[]`，不是 `null`。

```bash
curl -sS "http://127.0.0.1:8901/api/sessions?workspaceId=$WID" -H "Authorization: Bearer $AT"
```

→ `code:0`，`sessions[]` 的 `workspaceId` 全部等于 `$WID`；未知项目回 404 `114001`。

```bash
curl -sS -X DELETE "http://127.0.0.1:8901/api/workspaces/$WID" -H "Authorization: Bearer $AT"
```

→ 测试项目回 `200 {"code":0,"message":"","data":{"status":"deleted"}}`；默认项目回 `409 {"code":114005,"message":"默认工作区不能删除","data":null}`；有活 run 回 `409 {"code":114006,...}`。

```bash
curl -sS "http://127.0.0.1:8901/api/sessions/$SID/subagents" -H "Authorization: Bearer $AT"
```

→ `code:0`，`subagents[]` 每项含 `saId/agentName/status/createdAt`；`status=complete` 的项在页面上有「继续」。

### 4.3 浏览器（活体验收）

1. 登录后导航出现「项目」；项目页列出当前租户下自己的项目。
2. 新建项目 → 列表出现；改名 → 列表名变化；刷新页面仍在。
3. 展开项目会话 → 与 `GET /api/sessions?workspaceId=` 的数量一致；打开一场 → 回对话页且历史出现；再点「开新对话」→ 新消息 `POST /api/runs` 带该项目 id，`GET /api/sessions/:id` 的 `workspaceId` 等于该项目。
4. 点项目删除 → 弹窗出现；取消 → 项目还在；确认 → 项目消失，项目下会话也不在当前列表里。
5. 点会话删除 → 弹窗出现；取消 → 会话还在；确认 → 会话消失；若删的是当前会话，对话页清空。
6. 默认项目删除 → 弹窗内显示服务端 `114005` 文案，项目不消失。
7. 在会话目录放一份完整 wire（metadata + terminal）→ 对话页「子代理」条计数 +1；展开看到规格名、`sa_id`、已完成；点「继续」→ 输入框出现带 `sa_id` 的指令，且不自动发送。删除这份 fixture 后计数回落。

- **不做共享项目/协作编辑**：doc/42 已拍不做。
- **不改后端契约、不改存储形态、不改业务码**。
