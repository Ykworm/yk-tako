## 0. 一句话结论

后端一直允许不同会话并发跑（会话闸 `one_live_run_per_session` 只管同一场，租户容量闸默认 8）；**限制全在前端**：整个应用只调用一次 `useChat()`，切会话就是把这唯一一份状态清空重填。本篇把「谁在观察」从一份全局闭包变成一组并行实例——切走只是换 `activeChat`，旧实例的轮询、草稿、排队消息、游标都留在原地。

## 1. 病灶：两个会真实发生的故事

### 故事一：切走即失联

用户想让 agent 在 A 里跑一段两分钟的长任务，切到 B 看另一场对话。

1. 在 A 发消息，气泡开始流式输出；
2. 点侧栏 B：`openSession` 第一行 `pollToken++`（`chat.ts` 的轮询令牌），A 的帧轮询循环在下一个 `await` 后看到令牌失效就 `return`；
3. 服务端的 run 照样跑完，但前端不再拉它的帧、不再收口；
4. 切回 A 时 `reconcile()` 从头重拉历史、有活 run 就 `frames(0)` 重放——**能恢复，但中间发生了什么（跑完、等人提问、失败）当场没人知道**；侧栏也没有任何标记。

### 故事二：切走即丢件

1. 在 A 输入框写了一段没发的话，或 A 正忙时又发了一条（进 `pending` 队列，等本轮收口后自动投）；
2. 点侧栏 B：`openSession` 把 `draft`、`pending`、`attachments` 全部清空；
3. 切回 A：草稿没了，排队消息也没了，而且是**静默消失**——界面不提示这条消息没发出去。

这两个故事不修，多会话就不是「并发」，而是「轮流霸占同一个前端」。

### 端到端链路（改动后的每一环都能点名）

```
用户点侧栏某场会话
  → App.vue openChat(id)：池里已有同 sid 实例就只 activate，没有就新建 useChat() 并 openSession
  → activeChat 换人：旧实例 setActive(false)（不再抢写 localStorage 的「最后打开的会话」），新实例 setActive(true)
  → 旧实例自己的轮询循环照旧每 400ms 拉 GET /api/runs/{runId}/frames（服务端纯 LRANGE，多读者无限制）
  → 帧写回旧实例自己的 bubbles / 游标（不碰激活实例）
  → 用户切回：模板直接绑定该实例的 bubbles / draft / pending，不重新 reconcile
  → 会话被删 / 换租户 / 超上限：dropChat 停轮询、清队列、移出池
```

## 2. 机制：实例管理器

### 2.1 App.vue 侧（[App.vue:64](file:///Users/yuweikang/dev/ykcode/learn/yk-tako/yk-tako-eino/web/src/App.vue#L64)）

- `chatList = shallowReactive<ChatInstance[]>`：本 tab 打开过的实例。用 `shallowReactive` 是因为实例内部已经是原生 `ref`，不需要再被 Vue 深包一层。
- `activeChat = shallowRef<ChatInstance>`：当前显示的那个。
- 对外**保持同名导出**：`sessionId / bubbles / draft / attachments / pending / loadingOlder / atStart / busy / activeWorkspaceId / sessionGone` 全部改成读 `activeChat.value.*` 的 computed（`draft` 可写，set 写激活实例）；`send / loadOlder / reconcile / resumeRun / answerQuestion / setActiveWorkspace / showTenantSession` 转发到激活实例。模板与既有 watch 几乎不用改。
- `openChat(id)`（`:137`）：池里已有同 `sessionId` 的实例 → 只 `activate`；没有 → 新建实例、`openSession(id)`（**只有新实例才 reconcile**，避免重复渲染）。
- `activate(next)`（`:122`）：旧实例 `setActive(false)`、新实例 `setActive(true)`；**当前若是空白实例（无 sid）则切走即丢弃**——它没有可回到的入口，保留只会变成幽灵。
- `startNewChat(workspaceId?)`（`:150`）：新建空白实例并激活；当前有 sid 的实例留在池里后台继续跑。

**没它会怎样**：如果仍靠「清空 + 重建」，旧实例的轮询只能被全局令牌打断——这正是现状；管理器把「谁在观察」变成一组并行存在的对象，撤销全局令牌才有意义。

### 2.2 chat.ts 的最小改动（[chat.ts:334](file:///Users/yuweikang/dev/ykcode/learn/yk-tako/yk-tako-eino/web/src/chat.ts#L334)）

- 加 `active` 标志与 `setActive(v)`：`writeStoredSession` / `dropSession` 的 localStorage 写删**只在 active 时执行**（删前先比对当前存的值）。否则后台实例投递或收口会抢写「最后打开的会话」，刷新把你带回错误的会话。
- `reconcile(id?)`（`:832`）：带参用参；不带参仍读存储（首屏挂载路径不变）。
- `dispose()`（`:1080`）：停轮询、清 `pending` / `pendingTools`、`busy` 置 false，给删除事件与租户切换一个明确出口。
- 其余逻辑不动——每个闭包本来就自洽。

### 2.3 生命周期

| 事件 | 处置 |
|---|---|
| 切到已有会话 | 只切 `activeChat`；不 increment 旧实例的 `pollToken` |
| 新对话（当前实例有 sid） | 旧实例留后台继续跑；新建空白实例。**不弹确认框**——它留在侧栏，点得回来 |
| 新对话（当前是空白实例且有草稿/附件） | 弹确认框「这段还没发出去，新开后会丢。」；确认后丢弃 |
| 新对话（空白且无草稿） | 直接丢弃，不弹 |
| `session_deleted` | 按 id 找实例（不限于激活）：后台实例直接丢；正在看的保留实例、清成空白并显示死因横幅（`:931`） |
| `workspace_deleted` | 名单里的实例全丢；跨窗口事件只带项目 id，用「落点 = 该项目」认出本 tab 的会话，并把它们的落点退回默认项目（`:938`） |
| 切租户 / 退出 | 全部 `dispose` 后重建一份干净实例（`:161`） |
| 实例上限 | 有 sid 的实例最多 **8** 个；超出时淘汰「有 sid、不在跑、没草稿/附件、最久未激活」的那个，切回时重建（[chatpool.ts:17](file:///Users/yuweikang/dev/ykcode/learn/yk-tako/yk-tako-eino/web/src/chatpool.ts#L17)） |

淘汰抽成纯函数 `pickEviction`，单测覆盖：上限内不淘汰、取最久、busy/dirty/空白不淘汰、激活实例不动。

## 3. 项目落点（A3b，2026-11-01 用户补报后增加）

**用户报的缺口**：无法在指定项目里创建对话；空对话也不能选择/修改项目。

**核实结果**：项目页「开新对话」本身是通的（空白、有草稿两条路径实测 `POST /api/runs` 都带 `workspaceId`）；缺的是**对话页没有入口、也看不到落点**——`activeWorkspaceId` 原先只传给项目页。

**改法**：

- **落点跟着实例走**：两个空白对话可以各落一个项目，不再共用一个全局值。
- **输入区选择器**（[App.vue:2068](file:///Users/yuweikang/dev/ykcode/learn/yk-tako/yk-tako-eino/web/src/App.vue#L2068)）：`!sessionId` 时显示「项目：X」，选项直接复用侧栏 `sidebarGroups` 的项目数据（不新增接口）。发过消息后隐藏——会话已由服务端绑定项目，`api.ts` 也规定 `workspaceId` 只对新会话生效。
- **侧栏项目行「＋」**（[App.vue:1530](file:///Users/yuweikang/dev/ykcode/learn/yk-tako/yk-tako-eino/web/src/App.vue#L1530)）：项目行从整行一个 `<button>` 改成 flex 容器（左：原折叠按钮；右：`aria-label="在 <项目名> 新建对话"`），点击 = 在该项目下开新对话，不必先跳项目页。
- 落点持久化沿用 `tako.workspaceId.<tenantId>`，**只在激活实例写**；空白实例切换项目即写。

## 4. 侧栏「运行中」（本地信号）

`runningIds = {本 tab 里 busy 且有 sid 的实例}`（[App.vue:911](file:///Users/yuweikang/dev/ykcode/learn/yk-tako/yk-tako-eino/web/src/App.vue#L911)）。侧栏对应会话行加 `.recent-run` 徽标（`title="运行中"`，沿用 doc/51 的 accent token）。收口后 `busy` 变 false，标记自动消失，不重拉列表。

**边界**：这是**本 tab 的一手信号**，不是服务端事实——刷新页面或用另一台设备起的 run 不会出现在这里。见 §6。

## 5. 不做（及原因）

- **多栏同屏**：布局、输入焦点、窄屏要整体重做，与「同时推进几场」的核心诉求无关。形态已拍为「单主视图 + 后台保留」。
- **刷新/跨 tab 的运行状态**：需要列表接口加 `liveRunId` + 重拉或事件机制，见 §6。
- **每会话滚动位置记忆**：切回时滚到底，够用。
- **后台轮询降频**：先保持 400ms（每场约 2.5 请求/秒，租户上限 8 场 → 最坏约 20 请求/秒，本地无压力）；要降频改一个常量即可。
- **空白会话草稿落盘**：切走即丢（与现状一致）；要保留得先定义「草稿存在哪」。

## 6. 后置阶段 P1：列表接口带运行状态

`GET /api/sessions` 每项加 `liveRunId`（可顺带 `lastRunStatus`）。

- **启动条件（任一）**：① 需要刷新页面后仍看到「运行中」；② 需要看到别的 tab/手机起的 run；③ 侧栏要标「待答」（同样需要跨实例/跨端事实）。
- **为什么不在本轮**：它改契约字节（`expected.json`、`19v6-04`、`contract_test.go` 同批），且当前没有 run 开始/结束事件——列表不会自己重拉，还得配「有活跃 run 时定时重拉」或新增 run 事件，工作量与风险都超出「让前端同时带几场」本身。
- **落地时的第一个动作**：`curl GET /api/sessions`，期望每项多一个 `liveRunId` 字段。
- 眼下不做的两条替代路（备查）：侧栏逐行 `GET /api/sessions/:id`（N+1）；给侧栏每场建轮询实例（更贵）。
