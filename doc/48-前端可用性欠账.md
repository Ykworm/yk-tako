> 1. **Vue 3 陷阱**：`p.x ?? (p.x = {...})` 的**赋值表达式值是 raw 对象、不是 reactive proxy** → 后续赋值绕过响应式 set 拦截器 → **数据进了内存、DOM 不更新**。精确的触发条件是「赋值与改值之间**隔着 await**」：赋值标脏 → await 期间 Vue 渲染一次（读到当时的值）→ 之后的 raw 赋值不再标脏 → 界面停在 await 那会儿的样子。`ProjectsView.vue` 的 `loadFiles` 就栽在这（文件列表永远空白）。`chat.ts` 的 `upsertQuestion`（**doc/47 的问答主界面**）是**同一个写法、但不是同一个 bug**——它赋值后紧接着 push、中间没有 await，渲染发生在 push 之后，所以显示正常；仍改成「先判空再赋值、再读出来用」，是防将来有人在中间插 await。**回归网**：`web/test/reactive-trap.test.ts`（四条断言，含一条把「哪种形态会坏」钉死的对照）。
> 2. **`.stage` 缺 `min-height: 0`**：窄屏下 `.app` 变 column 方向，flex item 默认 `min-height:auto` 不肯收缩 → `.stage` 被对话内容撑高 → **body 溢出 126px、页面能滚** → 登录时聚焦密码框把页面滚下半截，**顶部的导航全被推出视口**（真实手机浏览器同样会这样）。
> 3. **`scrollBottom()` 在空列表时也滚**：空态「从一句话开始」被推出视野（窄屏尤其明显）。改成空列表时 `scrollTop = 0`。
> 4. **拆 form 后保存会连带提交别的卡片**：在「模型」卡片点保存，会把「密钥」卡片里**还没保存**的编辑一起提交 —— 「各有各的保存」就名存实亡。改成：只提交本卡片的编辑，其余用**服务端已保存的值**（`savedConfig`）原样带回。
> 5. **限宽用 `width` 不生效**：`.projects` / `.cfg` / `.stack` 是 flex item（`flex: 1` → `flex-basis: 0%`），**width 会被顶掉** → 宽屏留白根本没修掉。改用 `max-width`。
> 6. **markdown 每次渲染都重算**：`v-html="renderSafe(b.text)"` 在模板里，流式输出时每个 token 到达都要把**所有**气泡重新 parse + sanitize 一遍。加 `v-memo="[b.text]"`。

> 9. **playwright 测试污染开发库**：断言发的消息会在开发库留下会话。断言现在自己收尾删掉。
> 10. **拆 form 的修复自己引入了一个新 bug**：保存某张卡片后调 `loadConfig()` 全量重载，**把用户在其它卡片里还没保存的编辑一起冲掉**（在「密钥」卡片点保存 → 「模型」卡片里刚填的模型被覆盖回旧值 = 用户白填了）。改成：保存后**只更新「已保存值」里刚提交的那一块**，编辑框保持原样；已标记删除的行从表里移除（删除已生效，「撤销」无意义了）。回归网：`web/e2e/ui.spec.ts` 的「保存一张卡片不会冲掉另一张卡片里未保存的编辑」（旧行为下判红）。

### 2. Loop A · 对话面

对话页是唯一的高频页面，先修它。

#### A1 · Markdown 完全不渲染（**P0 · 契约违背**）

**病灶。** [doc/19-v6/19v6-03](19-v6/19v6-03-存储形态与生命周期.md) 第 118 行写着：「`text` 里的 `\n` 原样保留，**客户端按 markdown 渲染**，排版不受影响。」而 `App.vue:932` 是 `<p v-if="b.text" class="bubble-text">{{ b.text }}</p>`——纯文本插值，一个标签都不多。

实测（2026-10-23，模型被明确要求输出 markdown）：回复里的 `## hello.txt 说明`、`| 属性 | 值 |` 表格、` ```text ` 代码块、`1. 2. 3.` 列表、`**加粗**`，**全部以字面符号显示**。用户看到的是一堆管道符和井号。

**为什么这件事是 P0 而不是「美化」。** 模型输出 markdown 是这个系统的常态，不是意外：`doc/19-v6-07` 里 compact 摘要本身就是用 `##` 槽头组织的 markdown 骨架；用户给模型的指令（"整理成待办清单"、"写份说明"）几乎必然引出 markdown。**现在每一轮对话都在把模型的结构化输出退化成符号噪音**，用户要自己把 `|` 和 `---` 翻译回表格。而且这不是"少实现一个功能"，是**v6 文档写明的渲染责任从来没被实现**——按 AGENTS.md「与代码冲突时先判断哪一边过期」，这里过期的是代码。

**做什么。**

1. 新增 `web/src/markdown.ts`，导出三个函数：

   | 导出 | 做什么 | 碰 DOM 吗 |
   |---|---|---|
   | `renderMarkdown(text): string` | `marked.parse(text)` → HTML 字符串 | **否**（纯函数） |
   | `sanitizeHtml(html): string` | `DOMPurify.sanitize(html)` | 是 |
   | `renderSafe(text): string` | 前两者串起来 | 是（浏览器里跑） |

2. 依赖装两个：`marked@18.1.1` + `dompurify@3.4.17`（**选型出处见下**）。
3. `App.vue` 的气泡正文从 `{{ b.text }}` 改成 `v-html="renderSafe(b.text)"`。
4. 样式：给 `.bubble-text` 补 markdown 元素的排版规则（标题字号、表格边框、代码块底色、列表缩进、行内代码底色）。

**为什么是 `marked` + `dompurify`（选型出处，不是拍脑袋）。** 参照仓库里三家同类产品的现成选型：

| 参考实现 | markdown 库 | 消毒 |
|---|---|---|
| **pi**（`ref-agent/pi`，TS agent，doc/16 §2b 的主要参考） | `marked@18.0.11`（TUI + coding-agent） | — |
| **opencode**（`ref-agent/opencode`） | `marked@18.0.11` | `dompurify@3.4.14` |
| **WeKnora**（`ref-agent/WeKnora`，Vue 聊天） | `marked@^17.0.5` | `dompurify@^3.4.11` |

**三家全部是 marked，没有一家用 markdown-it。** 而且 marked 的 `sanitize` 选项早已废弃（官方指引：改用 DOMPurify），所以「marked + DOMPurify」是这对库的现代标准写法——三家做法一致不是巧合，是这条路已经被走通了。

doc/16 §1 的借鉴纪律说「抄『问题本质』不抄『历史包袱』」。这里的「问题本质」是**「用成熟解析器 + 成熟消毒器」**，不是「用哪个包」——所以照抄这个**组合**是对的，不是抄历史包袱。

版本取当前最新（2026-10-23 查 npm registry）：**marked 18.1.1**（三家参考实现都钉在 18.0.x，同一大版本）、**dompurify 3.4.17**。

**代价与好处。** 代价：多一个依赖（DOMPurify 约 20KB min+gzip），且它是 **DOM-only** 的（Node 里跑要 jsdom）。好处：与三家参考实现一致（出问题时有人可对照）、marked 的 GFM 表格/任务列表/代码块开箱即用、生态成熟。

**这个代价怎么绕开。** 上表里 `renderMarkdown` 不碰 DOM → `node --test` 直接测它，**不需要为测试额外引 jsdom**；而「`<script>` 会不会被执行」这条 XSS 断言**放到 playwright 浏览器里测**（浏览器才是 DOMPurify 的真实运行环境）。

**每一步的输入输出。** 输入 = 气泡里的 `b.text` 原始字符串（runlog 里的原话，**服务端一个字都不改**）；输出 = 一段 HTML 字符串，交给 `v-html`。

**没它会怎样。** 已在 §0.3 讲透：模型所有结构化输出退化成符号噪音。

**一个必须一起处理的坑。** `b.text` 里还可能夹着 media 占位行（`[media seq=… path=… mime=… size=…B sha=…；…]`）。现在这些行是被 `parseMedia` 剥掉的（`api.ts` 的 `parseMedia` 过滤掉占位行、留下正文），所以**渲染的输入已经是剥干净的正文**，不含占位行。改造时**不要把整条 runlog 原文直接喂给渲染器**——那会把占位行当普通文本渲染出来。

**验收。** 机器断言用 Node 内置 test runner（零新依赖，Node 22 自带 `--experimental-strip-types` + `node:test`）钉住渲染输出：

```bash
cd yk-tako-eino/web && node --experimental-strip-types --test src/markdown.test.ts
```

| 输入 | 期望输出包含 |
|---|---|
| `## 标题` | `<h2>标题</h2>` |
| `- a\n- b` | `<ul>` 且含 `<li>a</li>` |
| `\| a \| b \|\n\| --- \| --- \|\n\| 1 \| 2 \|` | `<table>` 且含 `<th>a</th>` `<td>1</td>` |
| ` ```text\nx\n``` ` | `<pre><code class="language-text">` |
| `**粗**` | `<strong>粗</strong>` |

**XSS 那条要单独说清楚**：marked 本身**不转义**原始 HTML（它会原样输出 `<script>`）——这正是必须配 DOMPurify 的原因。所以 `<script>alert(1)</script>` 这一条**不能在 node 里断言**（node 里没有 DOMPurify），要放到 playwright：发一条含 `<script>` 的消息 → 断言页面把它当**文字**显示、`window.alert` 未被调用。

**这个分工是刻意的**：结构在 node 里测（快、零依赖），执行在浏览器里测（真实环境）。

浏览器活体（人工）：发一条要 markdown 的消息，回复里标题有层级、表格有边框、代码块有底色。

#### A2 · 对话页没有会话历史入口（**P0**）

**先说清楚不动的部分（用户 2026-10-23 表态：「很多 agent 都是项目下面挂着对话」）。** 「会话挂在项目下」这个**数据结构保留不动**——`sessions.workspace_id` 这一列不动、项目页的树形结构不动、`GET /api/sessions?workspaceId=` 不动。本条要补的只是**一个直接回到旧对话的入口**：结构照旧挂在项目下，但用户不必先想到「是哪个项目」才能回去。

**病灶。** 侧边栏只有「对话 / 项目 / 助手 / 团队」四个按钮，**没有任何会话列表**。想回到上一场对话，路径是：点「项目」→ 找到那个项目 → 点「查看对话」展开 → 在两场会话里靠标题认 → 点「打开」。而标题是模型用首句生成的，不是用户起的名。实测那个项目里两场会话叫「说一句 ho」「说一句 hi」——用户拿这两行字认不出哪场是昨天那场。

**关键事实（决定了这条有多便宜）。** `GET /api/sessions` **不带 `workspaceId` 时就列本人的全部会话（跨项目）**——`server.go:780` 的 `listSessions` 只在 `workspaceId` 非空时才校验项目可见性，否则 `ListSessions(ctx, p, scope, "")` 返回本人全部会话。前端 `api.ts` 的 `listSessions(workspaceId?)` 早就能这么调，只是 `ProjectsView` 永远带着 `workspaceId` 调。

**所以 A2 是纯前端改动，零后端。**

**做什么。**

1. 侧边栏 `rail` 的导航（`.nav`）下面加一个「最近会话」区，标题写「最近会话」。
2. 数据：`GET /api/sessions`（不带参数），**按 `createdAt` 倒序取最近 10 场**，每行显示会话标题（空标题显示「未命名对话」）+ 时间（`toLocaleString('zh-CN', {dateStyle:'short', timeStyle:'short'})`）。
3. 点一行 = 打开那场会话。复用现成的 `openSession(id)`（`chat.ts` 已导出，`ProjectsView` 的「打开」按钮就是调它）。
4. 当前正在看的那场会话，在列表里高亮。
5. 列表底部一行「在项目页里看全部 →」，跳到项目页。

**为什么是「最近 10 场」而不是完整树。** 对话页最常见的需求是「回到刚才那场」，不是「找三个月前某场」。完整树放在项目页（已有）。这两者不重复：一个是**快捷回跳**，一个是**归档检索**。

**输入从哪 / 输出到哪。** 输入 = `GET /api/sessions` 的 `sessions[]`（`{id,title,createdAt,workspaceId}`）；输出 = 侧边栏 10 行；点击 = 调 `openSession(id)` → 它走 `reconcile()` 重建对话（**已验证可用**：实测从项目页「打开」旧会话，历史完整回来了）。

**没它会怎样。** 用户每次想回到上一场对话，都要先猜项目名、再在会话标题里认字。

**验收。** 浏览器活体（两个窗口交叉核对）：

```
窗口 A（浏览器）：登录 → 对话页 → 侧边栏应出现「最近会话」区，列出 ≥3 场（按时间倒序）
窗口 B（终端）：curl -s -H "Authorization: Bearer $TOK" "$BASE/api/sessions" | jq -c '.data.sessions[0]'
```

期望：窗口 A 列表第一行的标题与窗口 B 的 `sessions[0].title` **逐字相同**（时间倒序必须对）。点第一行 → 对话区出现那场会话的历史气泡。

#### A3 · 运行中没有「停止」按钮（**P1**）

**病灶。** 引擎有 `POST /api/runs/:runId/stop`（`server.go:75`，doc/17 §4 手动停止，带条件 UPDATE 竞态裁决 + 跨副本 cancel）。前端一次都没调过。用户让模型干一件耗时的活，做到一半发现方向错了，**唯一的办法是刷新页面**——那场 run 还在服务端跑着，token 还在烧。

**做什么。**

1. `api.ts` 加 `stopRun(runId: string): Promise<{ status: string }>`（走现成的 `request()`，信封统一）。
2. `chat.ts` 加 `stopCurrent()`：拿当前 `busy` 那条气泡的 `runId` 调 `stopRun`；成功后把该气泡 `state` 置 `'stopped'`（`chat.ts` 的 `closeOut` 已有 `stopped` 分支，`App.vue:947` 已有「已停止，没有写进历史」的文案，**不用新写文案**）。
3. `App.vue` 的 composer 栏：`busy` 为真时，把状态提示「正在回复」**换成「正在回复 · 停止」按钮**；点了就调 `stopCurrent()`，按钮进入 disabled + 「正在停止…」。
4. 排队中（`pending.length`）不显示停止——那不是 run，是本地队列（`chat.ts` 的 `pump`）。

**每一步的输入输出。** 输入 = 气泡上的 `b.runId`；输出 = 服务端把 run 标成 `stopped` → 前端把那条气泡渲染成「已停止，没有写进历史」。

**没它会怎样。** 方向错了只能刷新；正在跑的那场 run 继续烧 token，用户还以为它停了。

**验收。** 浏览器活体：

```
窗口 A（浏览器）：发一条要跑很久的请求 → 状态栏出现「停止」按钮 → 点它
窗口 B（终端）：curl -s -X POST -H "Authorization: Bearer $TOK" "$BASE/api/runs/$RID/stop" | jq -c .
```

期望：窗口 A 的气泡变成「已停止，没有写进历史」；窗口 B 在 A 点之前调会回 `{"code":0,…,"data":{"status":"stopped"}}`（幂等：A 已经停过再调一次仍回 `stopped`，不报错）。

#### A4 · 「子代理 0 / 展开」条常驻（**P2**）

**病灶。** 对话区顶部常驻一条「子代理 0 / 展开」（`App.vue:868`，`v-if="sessionId"` 就显示）。没有子代理时它占一行，还带着一个「展开」按钮诱导用户去点空的。实测每一轮对话、每一个会话，这张条都在。

**做什么。** 改成**有子代理才显示**：`v-if="sessionId && (subagents.length || subagentsLoading || subagentsError)"`。「展开 / 收起」两个按钮保留（`subagentsOpen` 状态不动）。加载中与出错时仍要显示（否则用户点了「展开」看到空白，不知道是加载中还是真没有）。

**没它会怎样。** 每轮对话顶部多一行噪音，并训练用户去点一个永远空的开关。

**验收。** 浏览器活体：新会话（没有子代理）→ 对话区顶部**不出现**「子代理」字样；展开过的会话仍然能列出子代理。

#### A5 · 侧边栏工作区名被截断（**P2**）

**病灶。** 侧边栏底部的当前工作区名显示成 `a7-envelope...`（省略号截断）。这个名字是用户区分「我现在在哪个工作区」的唯一标识——多开一个工作区后，截断成 `a7-envelope...` 和 `a7-envelope-t...` 的两个工作区**在界面上分不出来**。

**为什么会被截断。** 侧边栏宽 15.5rem（248px），底部一行挤着：头像（30px）+ 工作区名 + 箭头（14px）+ 「退出」（45px）。留给名字的只有 96px 左右，`a7-envelope-test`（15 个字符）放不下。

**做什么（按代价从低到高，三选一，方案里定第 1 个）。**

1. **（推荐，纯 CSS）** 名字超长时**不截断，改成两行**，并给 `.who` 加 `min-width: 0` + `word-break: break-all`；`.switcher-btn` 的 `title` 属性放全名，鼠标悬停可见。同时把「退出」按钮挪到**头像的右侧**（或收进工作区切换菜单里），把宽度还给名字。
2. 缩短「退出」为图标按钮（可读性换宽度）。
3. 侧边栏加宽到 17rem（影响所有页面，不推荐）。

**没它会怎样。** 多工作区场景下用户分不清自己在哪。

**验收。** 浏览器活体：侧边栏底部的工作区名**完整可见**（不出现 `…`）；名字超长时换行显示且不撑破侧边栏。

### 3. Loop B · 产出可达

#### B1 · agent 产出的文件，用户拿不走（**P0**）

**病灶。** 用户让模型「把结果写成 report.md」，模型说写好了。**然后没有然后**：

- 项目页只列项目与项目下的会话，**不列项目目录里的文件**；
- 聊天里那行 `report.md` 是个 `.bubble-file` 文字片（`App.vue:925`），**不可点击**；
- `GET /api/media` 挂着 `authn` 中间件要 Bearer 头，用户右键另存、贴进新标签页都会 401。

**agent 干完活，成果锁在服务端目录里，用户唯一能带走的是模型复述的那段话。**

**关键事实（决定了这条要多少工作量）。** `getMedia`（`server.go:1278`）的 path 形如 `workspaces/<wid>/<相对路径>`：它先 `parseSessionMediaPath` 拆出 wid，再 `VisibleWorkspace` 校验项目可见性，然后把 root 设成**项目目录**、`rel` 设成 wid 之后的相对路径，最后过 `resolveInWorkspace` 那把围栏。**也就是说 `GET /api/media?path=workspaces/<wid>/report.md` 今天就能读到 agent 写出的文件。**

所以 B1 缺的只有两样：**① 一个「列目录」端点；② 前端的一个入口。** 字节取用复用现成的 `GET /api/media`，不新开下载端点。

**做什么。**

**① 后端新增一个端点**（本篇唯一的全新端点）：

```
GET /api/workspaces/:id/files?path=<相对路径，默认 ".">
```

- 成功体：`{"code":0,"message":"","data":{"path":".","entries":[{"name":"report.md","kind":"file","size":1234,"modifiedAt":"2026-10-23T…"},{"name":"sub","kind":"dir"}]}}`
- 围栏：复用 `resolveInWorkspace(root, path)`（`filetools.go:33`）——**越出项目目录与绝对路径一律 400 `111002`「路径不对」**（与 agent 侧工具同一把锁，还带符号链接逃逸检查，不新开一条能绕过的路）。**错误码按现状取 `111002`**，不是 `111001`：同一个 `resolveInWorkspace` 失败在 `product_api.go` 的 dev 文件端点上已经用 `111002`（`codeBadInput`「路径不对」），沿用同一个码，前端能复用同一套处理分支。
- 可见性：先 `VisibleWorkspace(ctx, wid, tenantID, userID)`，看不见回 404 `114001`。
- **内部目录不列**：`.media/`（入口媒体，doc/32）与 `.tako/`（**搜索截断落盘**，doc/21 H3：`<项目>/.tako/search/*.md`）不进 `entries`。用户不需要看这两样，看了反而困惑。（**更正**：子代理 wire 不在项目目录——它在**会话目录** `.tako/subagents/`，doc/39；这个端点碰不到它。）**但 `.media/` 里的图片仍然要能显示**——见下条。
- **符号链接不列**：symlink 条目直接跳过。它可能指向项目外，列出来等于泄露「那边有什么」，而点进去 `resolveInWorkspace` 也会挡住——列了是坏体验，不列是安全。
- 排序：目录在前，同类按名字升序（与 `list_directory` 工具口径一致）。
- 大小与时间：`size` 是字节数，`modifiedAt` 是 mtime（ISO8601）。

**② 前端**（2026-10-23 已落地，`web/src/ProjectsView.vue`）：

- 项目页每个项目卡片加一个「文件」区（默认收起，与「查看对话」并列的两个可展开区之一）。
- 展开时 `GET /api/workspaces/:id/files?path=.`，列出条目；点目录 → 往下钻（面包屑：`项目根 / sub`）；面包屑可点回任意一层。
- 取字节走 `GET /api/media?path=workspaces/<wid>/<相对路径>`（**前端要带 Bearer**，用现成的 `authFetch`）。因为要带 Authorization 头，**不能直接把 href 指过去**（浏览器直接导航不带 → 401），所以一律先 `fetch` 成 blob：图片出缩略图、文本出内容、其他给「下载」。
- **「预览」按钮按扩展名白名单给**（图片 png/jpg/jpeg/gif/webp/bmp/svg/ico；文本 txt/md/markdown/csv/json/log/yml/yaml/toml/html/css/js/ts/go/py/sh/xml/ini/conf）。**为什么不看 Content-Type**：`/api/media` 的 mime 表（`mediaMimeByExt`）只覆盖图片/pdf/音视频，`.md`/`.csv`/`.txt` 落到 `application/octet-stream`，blob.type 判断不出文本。服务端条目里也没带 mime 字段（那是字节出口的事），所以前端按扩展名近似——**判错的后果只是「少一个预览按钮」，不会出错内容**。
- 文本预览最多显示 2000 字，超出部分提示「用下载拿全文」。

**③ `.media/` 的可达性（2026-10-23 已查清，开放项关闭）。** 「内部目录不列」会让 `.media/` 里的入口图片从文件浏览器里消失。查了落盘口径（`media.go:69`）：**`.media/` 里只有用户上传的入口图**，文件名是内容寻址的 `sha256[:16] + 扩展名`（没有原名）；模型产出的图不走这里（模型自己 `write_file` 写进项目目录）。而入口图**在聊天气泡里全部能看**（`App.vue` 的 `<img class="bubble-media">`）。→ **不列 `.media/` 不会让用户失去任何入口**，这一条不用再改。

**每一步的输入输出。**

- 输入：项目 id + 相对路径；输出：该项目目录下的直接子项清单。
- 输入：`workspaces/<wid>/<相对路径>`；输出：文件字节（Content-Type 按扩展名，表外为 `application/octet-stream`，见 `mediaMimeByExt`）。
- 前端把两者接起来：点文件名 → 取字节 → 图片内联 / 其他下载。

**没它会怎样。** agent 的产出不可达。这个产品的价值主张是「agent 帮你把活干完」，干完的**东西**拿不走，价值就断在最后一步。

**验收。**

```bash
# 1) 新端点（这个 action 的契约拍）
curl -s -H "Authorization: Bearer $TOK" "$BASE/api/workspaces/$WID/files?path=." | jq -c .
# 期望：{"code":0,"message":"","data":{"path":".","entries":[...]}}

# 2) 越界挡死
curl -s -H "Authorization: Bearer $TOK" "$BASE/api/workspaces/$WID/files?path=../../etc" | jq -c .
# 期望：{"code":111002,"message":"路径不对","data":null}

# 3) 看不见的项目
curl -s -H "Authorization: Bearer $TOK" "$BASE/api/workspaces/$WID_NOWHERE/files" | jq -c .
# 期望：{"code":114001,"message":"找不到这个项目","data":null}
```

字节断言进 `scripts/acceptance/expected.json`（新用例「**用例 12**」——用例 10 已被 doc/47 的人审问答码段占用，编号不能撞）+ `doc/19-v6/19v6-04-验收-curl.md` 散文版**同批改**，`check-expected.sh` 守两边一致。

**为了让机器断言能造出「目录里有文件」这个前提**，断言器加了一个步骤 `op=seed_ws`（往项目目录里造文件/目录/符号链接——产出文件在文件系统上，SQL 造不出来）；项目目录布局 = `<workspace根>/tenants/<tid>/workspaces/<wid>/`，workspace 根由新环境变量 `TAKO_WS_ROOT` 给（默认 `<仓库根>/tmp/workspace-acc`）。

### 4. Loop C · 破坏性操作与文案

#### C1 · 默认项目跟普通项目长得一样（**P1**）

**病灶。** 系统「默认」项目在项目页里**跟用户自己建的项目完全一样**：有「删除」按钮、有改名按钮。点删除，弹窗先许愿：

> 「"默认"会被删除。项目里的 2 场对话会一起删除（保留窗口内仍可恢复）。项目目录里的文件会清掉。」

用户读完这段会以为文件要没了、点了「删除」，等来一句错误——服务端 `auth.go:169` 的 `codeWorkspaceDefault = 114005` **必然拒绝**（我核对过服务端实现）。

**为什么前端不知道哪个是默认项目。** `api.ts` 的 `Workspace` 类型注释写得很直白：「**默认项目不单独标 isDefault**，删除时靠 409 message。」于是前端只能等点了才知道删不掉。

**做什么。**

1. **后端**：`GET /api/workspaces` 的每个 workspace 对象加一个字段 `"isDefault": bool`（默认项目为 true）。加字段不改既有字段，**是增量，不是契约翻转**——但仍是字节变更，所以要进 `expected.json` + 19v6-04 同批改。
2. **前端**：
   - `api.ts` 的 `Workspace` 类型加 `isDefault?: boolean`。
   - 项目页：默认项目**不渲染「删除」按钮**（改成一句静态说明「默认项目不能删除」），**「重命名」也去掉**（改名默认项目没有意义，且会让用户失去「这是默认项目」的视觉标识）。
   - 项目名后面加一个「默认」徽标（跟「新对话落点」徽标同款样式）。
   - 「新对话落点」那一行的文案：**「默认项目」改成「默认」**，跟列表里的项目名对上（见 C4）。
3. **保留后端 409 作为兜底**（前端隐藏按钮不等于后端放松；老前端、直接 curl 仍要撞 409）。

**没它会怎样。** 每个新用户第一次进项目页，都会看到「删除」按钮加一段会清空文件的许诺，然后失败一次。

**验收。** 字节：`GET /api/workspaces` 的 `workspaces[]` 里默认项目那一项含 `"isDefault":true`，其余含 `"isDefault":false`；浏览器：默认项目卡片上没有「删除」按钮，有「默认」徽标。

#### C2 · 密钥 `••••` 是真实值，改一下就写成垃圾（**P1**）

**病灶。** `Configure.vue:255` 把密钥值设成**字面量 `'••••'`** 存进 `row.value`，同时 `row.masked = true`。用户在那个输入框里改字时，`@input` 只做 `row.masked = false`（`Configure.vue:493`），**不会清掉已有的 `'••••'` 占位符**。用户手一抖就是在 `••••` 后面续写，保存进去的密钥变成 `••••sk-xxxx`——**带占位符前缀的垃圾值**，这把密钥就此失效。

还有两条并行的删除路径：文案只说了「把格子清空再保存，会删掉它」，但界面上还有一个「移除」按钮（`Configure.vue:494`）**直接 splice 掉那一行、没有任何确认**。用户以为「移除」只是把它从列表里拿走，保存后它真的被删了。

**做什么。**

1. **密钥值不再是输入框里的真实值。** 改成 `type="password"` 的输入框 + 一个独立的「显示/隐藏」按钮（像登录页的密码框那样，`App.vue:842` 已有这个模式，直接抄）。
   - 服务端返回 `••••` 时：**输入框留空**，placeholder 写「已保存（留空则不改动）」。
   - 用户输入了内容 → `masked = false`，保存时用用户输入的值。
   - 用户没输入 → 保存时传 `••••`（服务端认这个占位符、保留原值）。
   - **这样「输入框里有什么」与「保存什么」永远是同一件事**，占位符永远进不了真实值。
2. **「移除」改名为「删除这把密钥」，并加二次确认**（复用现成的 `ConfirmDialog.vue`）：「删掉 DEEPSEEK_API_KEY？保存后这把密钥不再可用，模型调用会失败。」
3. **「清空格子删除」这条路径取消**（**已拍**，2026-10-23）。因为 1 改完后，「清空」和「输入新值」不再能靠「格子是不是空的」区分了。所以：
   - 输入框留空 = **不改动**（不是删除）；
   - 点「删除这把密钥」= 删除。
   - 一个输入框的「空」只该有一种含义。文案改成：「留空表示不改动；要删除请点删除按钮。」
4. `originalSecrets` 那段「删除的行在保存时写 `''`」的逻辑（`Configure.vue:283`）同步改成「只有显式点删除的行才写 `''`」。

**每一步的输入输出。** 输入 = 用户在输入框里敲的字符（空 / 非空）；输出 = 保存请求里 `secrets[name]` 的值（非空=用户值；`••••`=不改；`''`=删除）。

**没它会怎样。** 用户改一把密钥，改完就再也调不动模型了，而且**看不出是哪一步坏的**（前端显示保存成功）。

**验收。** 浏览器活体 + 字节交叉核对：

```
窗口 A（浏览器）：团队 → 设置 → 密钥 → 在 DEEPSEEK_API_KEY 的值框里输入 sk-test123 → 保存
窗口 B（终端）：curl -s -H "Authorization: Bearer $TOK" "$BASE/api/tenants/$TID/runtime-config" | jq -c '.data.config.secrets'
```

期望：窗口 B 里 `DEEPSEEK_API_KEY` 的值**不含 `••••` 前缀**（今天会返回 `••••sk-test123`，这是 bug 的证据）。

### 8.1 「清空密钥格子 = 删除」是什么意思

现在的界面长这样（团队 → 设置 → 密钥）：

```text
密钥
格子里仍是 •••• 时，保存不会改这把密钥。把格子清空再保存，会删掉它。

DEEPSEEK_API_KEY  │  ••••  │ [移除]
```

三个事实：

1. **格子里的 `••••` 不是密钥本身**，是服务端给的占位符，意思是「这把密钥已经存在，但我不给你看真值」。
2. 今天的 `••••` 是**真的躺在那个输入框的 value 里**。用户以为那 4 个点是遮罩、点进去会看到真密钥——其实点进去看到的就是 4 个点。
3. 于是有**两条删除路径**，界面只用一句话带过：
   - **路径甲**：把格子里的 `••••` 删干净（留空）→ 保存 → **这把密钥被删除**。
   - **路径乙**：点「移除」按钮 → 那一行从界面上消失 → 保存 → **这把密钥也被删除**（而且「移除」这个词听起来只是「从列表里拿掉」，**没有任何确认**）。

**更要命的是第三条路径**——用户想**改**一把密钥，不是删：

- 他点进值格子，**全选** `••••`，敲下新密钥 `sk-abc123` → 没问题，格子变成 `sk-abc123`，保存正确。
- 但他**没全选**，只是在末尾接着敲、或者只删掉一个点 → 格子变成 `•••sk-abc123` → 保存进去的就是这个带占位符前缀的垃圾串 → **这把密钥当场失效**，而界面照样弹「已保存」。

所以这条要拍的是：**输入框的「空」到底该表示什么。**

- **现状**：空 = 删除（甲），外加一个「移除」按钮也 = 删除（乙），外加「空 = 不改动」这条**只在一个字都没动的时候**才成立——**同一个状态三种含义**。
- **建议**：输入框的「空」**只**表示「不改动」（这是绝大多数人改设置时的期望）；删除走**单独的按钮 + 二次确认**。这样「输入框里有什么」与「保存什么」永远是同一件事，占位符永远进不了真实值。

**另外一条要你确认的（不算拍板，是澄清）**：A2 我按「项目下挂对话的结构保留，只在对话页加一个『最近 10 场』的快捷入口」写。如果你要的是**完整的项目-会话树也搬到对话页**，那是另一套（侧边栏要变三栏），施工量翻倍，请明确说一声。
