A2 · 存储列与真写入路径（探针扩写）

改什么

  • RunTask 加 Result string（AutoMigrate 自动加列）。
  • UpdateTask 加 result 参数：事务内先查行 → effective = in.Result || row.Result → 调 A1 的闸；拒绝返回哨兵 ErrTaskResultRequired（状态与 result 都不写）； 通过则 truncateRunes(result, 300) 后落库。
  • TaskUpdate handler 把哨兵转成错误文本（toolErrorText 不会重复加「错误：」）。
  • 探针扩成 action=create / update / list（真写库，租户取登录身份，run_id 由调用方给）。
  • 单测 TestUpdateTaskRequiresResultOnComplete：拒绝后行仍 in_progress 且 result 空； 通过后两列一起写；350 字截断标记。

为什么

  • 闸必须落在唯一写路径上（工具与探针共用），否则模型可以绕过； 列不落库，下一场 TaskList 读不到，整个方案无意义。

怎么验收

  1. curl -s -X POST "$TAKO_BASE/api/dev/task-check" -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"action":"create","run_id":"r_probe_a","subject":"探针任务"}'
    期望：data = {"taskId":1,"status":"pending"}。
  2. 拒绝路径： 
    curl -s … -d '{"action":"update","run_id":"r_probe_a","task_id":1,"status":"completed"}'
    期望 allowed:false + planning §2.2 的错误文本；随后 action=list 期望 status:"pending"、result:""。
  3. 通过路径：… "status":"completed","result":"p95=1.8s" → allowed:true；再 list 期望 {"taskNo":1,"status":"completed","subject":"探针任务","result":"p95=1.8s"}。
  4. 超长：result 塞 350 字 → list 里 result 尾部是 …〔截断：原 350 字符〕。
  5. go test ./internal/runengine（既有 5 处 UpdateTask 调用同步改签名）。

这一拍回答什么：闸在真写入路径生效吗？拒绝会不会留下半截状态？下一场读得到吗？
