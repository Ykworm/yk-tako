1. 现状快照（2026-10-07）

1.1 构成

v6 新仓 yk-tako-eino/ 的全部 = 运行引擎 + 单会话聊天 UI + 模型配置层。

位置 内容
cmd/yktako/ 单入口；旗标 -engine -batch-window -dev -redis -pg -lease-ttl -lease-renew；启动双 fail fast（Redis / PG / 模型配置任一不可达不起进程）

不存在：工具、护栏、看板、压缩、子代理、记忆、RAG、评测——旧线（v1–v5）已随 backup 整体出仓。

1.2 引擎已验收能力（A 系列全部销账）

  • 四 API：POST /api/runs · GET /api/sessions/{sessionId} · GET /api/runs/{runId}/frames · GET /api/sessions/{sessionId}/log（+ dev DELETE /api/dev/reset）。 纯拉模型：无 SSE / 长连接 / 推送，实时性 = 客户端轮询节奏。
  • 存储（D1 后）：PG 四表 sessions / runs / runlog_entries / run_model_messages + Redis 两键 tk:runlive / tk:draft（runlive 终态 TTL 300s，回收参数非正确性参数）。
  • 闸 = runs 活行部分唯一索引（one_live_run_per_session），插入冲突即 409； 租约 lease_until（出生即带）+ worker watchdog 续约（CAS：UPDATE 影响 0 行 = 判死停续）。
  • 双游标：eventOffset（run 内、临时，挂 frames）与 runlogOffset（session 内、永久，挂 log）， 各自只在自己端点前进；单批上限 W（-batch-window，dev 200）。
  • kill -9 自愈链（已实测）：lease 判死 → 两键蒸发 → frames gone → 会话自动解锁 → 再 POST 202； 死 run 不进历史（error 形状）。
  • provider 归一层：claude / openai / eino 三 translator——加厂商 = 加 translator，帧协议与存储侧不动。
  • 验收网：curl baseline（①–⑫ + ⓐ–ⓓ，字节级）+ go test ./internal/runengine/ -count=1 16 条真实例网 （真 6390 独立 db + 5433 临时库）+ 变异检查 M1–M10。

2.2 对照要点（每源最值得偷什么）

pi（TS 极简 agent）：

  • 工具面：默认工具集只 read/bash/edit/write 四项（doc/16 说的「4 原语」实指它）； codemode——模型写 JS 在 QuickJS 沙箱一次并列调多个工具、结果过滤后才进上下文； MCP 工具默认不注入，BM25 搜索按需加载。
  • 上下文面：compaction 写 CompactionEntry——firstKeptEntryId 划保留区、原条目永不删除； transformContext → convertToLlm 两段转换（自定义消息可只给 UI 不进模型）。
  • 会话面：树状 JSONL（entry 带 id/parentId，只 active branch 进上下文），/tree 原地分支、/fork、/clone。
  • 分发布局：Skills 走 agentskills.io 标准（SKILL.md；启动只注入 name+description，渐进披露）； Pi Packages（npm/git/本地）一包同带 skills/extensions。
  • 评测：vitest-evals；docs-lift（Docker 双镜像 with_docs/without_docs 配对算「文档提升」）。
  • 注意：pi 的多客户端/崩溃恢复在实验包（durable/chord），且明确不做 CRDT 离线合并、 storage 无跨进程锁——tako 的「多副本闸 + 租约 + 双游标」在这条线上已更彻底；树状会话才是它领先的形态。

WeKnora（Go，Eino 类库参考）：

  • RAG 工程全套：docreader（独立 Python gRPC 解析）/ chunker（父子块 + 标题面包屑）/ 向量库抽象 ~10 后端（pgvector、ES、Qdrant、Milvus…）/ 混合检索 RRF 融合 / rerank / GraphRAG。
  • 记忆：asynq 异步抽取 → consolidate 合并 → topic 归类；向量+词法混合召回； 常驻块（profile/偏好）+ 按需块（fact/task/interest）；agent 有 search_memory 工具。
  • agent：手写 ReAct 引擎（非 Eino）+ 工具审批 + MCP client/manager/OAuth。
  • 评测：指标族（Precision/Recall/NDCG/MRR/MAP/BLEU/ROUGE）+ parquet 数据集跑真实管线。
  • 产品面：~30 家 provider 分型（chat/embedding/rerank/vlm/asr）、多租户 RBAC、IM 十渠道、 数据源连接器、Langfuse 追踪。
  • 护栏（doc/16 §4）：只借工程不学定位——正本永远结构化存储，向量库只是可重建派生副本； 只在「agent 回忆历史」场景服务 agent。

steer 附注：运行中插话——pi 有 steering/follow-up 双队列，WeKnora 有生产版收件箱 （inject/after 双模式、队深上限 10、SteerID 幂等键）。tako 现裁 = 409 + 客户端本地排队（B1 已落）， 属「明确不做」，不是遗漏。

2.3 归纳

引擎层（多副本正确性、崩溃自愈、纯拉取收敛）是刚打稳的地基，比两个参考源的同位物更彻底； agent 能力层几乎全空（重建 + 从未做两叠）；产品层（多会话管理、多入口、多模态、多用户）按 T3 排队。
