5. 新增／修改文档的规则

  1. 编号与位置

    • 执行期台账：tmp/<方案名>/（本地，不入库），验收后按第 8 条留档。
  2. 头注必须写四件事：性质（方案／实现真源／讨论稿／存档）、状态（✅／🔶／⬜）、日期、代码落点。写了“未定案”的文档不能被当成施工真源引用。
  3. 替代关系写在头注：新文档取代旧文档时，旧文档头注加“已被 X 取代”，新文档写“取代 Y”；不删除旧文。
  4. 同一机制只留一份真源：其他文档只写指针，不复制条款；发现两处冲突，先改真源，再改指针。
  5. 代码落点必须是真实路径：没有代码就写 —（文档／验收／记录），不要写已删除的包。
  6. 新增或改状态时同步本索引：同一提交里更新对应行；纯错别字修正除外。 动了产品能力的增减或状态翻转，同批还要更新 doc/16（§2 能力表 + §2c 横切契约 + 头注基线日期）——本索引是目录页，doc/16 是结论页，两个都得更，只更一边总纲的「现状」就是假的。收尾跑 scripts/check-master-plan.sh（比对本表 §1 的现行真源编号与 doc/16 的引用，漏引即失败）。
  7. 四类归属：现行真源（doc/ 顶层编号文档）、决策档案（doc/problems/）、记录（doc/log/）、归档（doc/archive/）。四者不互相冒充。 时效变化不搬家，只改状态：一篇方案过时了就在头注改状态或标「已取代」；只有被整代取代（旧线、旧引擎代际）才进 doc/archive/。
