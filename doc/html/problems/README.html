性质：决策档案，不是方案真源。每条回答「当时遇到了什么问题、桌上有哪些候选、为什么选这个、代价是什么、今天还成不成立」。 收录判据：只收设计选择题——有备选、有代价、有裁定。纯 bug 修复只在它暴露设计问题时顺带收。 素材口径：doc/（定了什么）+ tmp/ 台账（当时怎么想）+ git/代码（真做了什么）。三者冲突时以代码与用户原话为准。 最后核对：2026-10-31，共 43 条。模块划分与代码落点见 doc/53-模块地图.md。

0. 怎么用

  • 想找「为什么是这个设计」：先按模块下表找到问题，再读那条的 §2「候选与代价」与 §5/§4「同族小裁定」。
  • 想复核某条裁定今天是否仍成立：每条 §6/§4「证据」给了代码符号与复核命令；§7/§6「现状」写明「仍有效 / 已翻转 / 未落地」。
  • 想新增一条：在 doc/problems/<问题名>/问题与方案.md 落文件，问题名用一句中文问句（不带编号）；写完回到本表登记一行，并在对应模块的 doc/53 小模块后加反链。词表：已落地 / 部分落地 / 方案已定·未施工 / 已翻转 / 待拍（有候选、没裁定，只记现状与代价）。

每篇固定六到七节：1 场景与病灶（讲一个会真实发生的失败故事）→ 2 候选与代价（表）→ 中间按需拆真身 → 同族小裁定（表）→ 证据（方案 § / 台账 § / 代码符号 / 复核命令 / 活体验收）→ 现状（仍有效 / 已翻转 / 未落地 + 同族链接）。
