## 1. P0：子代理名字不合法会拖垮整个租户的 run

**病灶故事**：运营在「助手 → 子代理 → 新建」里建了一个叫 `qa 空格` 的助手，保存成功、列表正常。此后再发任何消息——哪怕是「只回复 ok」——页面都只显示「失败，没有写进历史」。引擎日志里是：

```
agents: 3 spec(s): coder, qa 空格, researcher
[NodeRunError] status code: 400 ... Invalid 'tools[25].function.name': string does not
match pattern. Expected a string that matches the pattern '^[a-zA-Z0-9_-]+$'
```

**为什么会这样**：助手名字同时是三样东西——AgentTool 的工具名、runlog 里的 `agent` 值、厂商请求里 `tools[i].function.name`。最后一项有硬约束（`^[a-zA-Z0-9_-]+$`），而我们在**保存、导入、落盘解析**三个入口都没校验。

**不修的后果**：用户不知道是自己建的东西坏了，只会认为「这个产品今天不好用」；而且坏配置会一直留在租户里，重启引擎也不会好。

**怎么修**：一个规则 `^[A-Za-z0-9_-]{1,64}$`，三处都拦：

| 入口 | 今天 | 改后 |
|---|---|---|
| `POST/PUT /api/tenants/:id/agents` | 只 trim + 非空 | 400 `111002`「助手名字只能用字母、数字、下划线、连字符（1–64 个字符）」 |
| `POST /api/tenants/:id/agents/import` | 只查重名 | 同一句话 400，整批不落库 |
| 工作区 `.md` 规格（`parseAgentSpec`） | 只查 frontmatter 形状 | 这条拒载并打日志；其余规格照载，run 不受影响 |

**验收**：三个入口各打一次（curl 见台账），外加 `agents_test.go` 两条单测。

## 2. P1：刷新会把「停止/失败」这一轮抹掉

**病灶故事**：用户让模型数 1 到 5000，发现不对，点停止。屏幕上立刻出现「已停止，没有写进历史」——然后他刷新了一下页面，这句话和气泡一起消失，只剩自己那条消息。他会以为消息没发出去。

**为什么**：停止与失败在 runlog 里都没有 assistant 定稿行。实时路径靠 `closeOut()` 查状态补上这句提示；刷新走 `reconcile()`，那里只认「有活 run」和「崩溃可续（interrupted）」两种，`stopped` / `error` 没有分支。

**怎么修**：`reconcile()` 补一条分支，用 `lastRunStatus` + `lastRunId` 重建一条空的 assistant 气泡，`state` 分别置 `stopped` / `error`——渲染复用现有 note 文案，不加新组件。

**验收**：发长任务 → 停止 → 刷新 → 提示还在；再发一条历史顺序不乱。

## 3. P1：等人面板把输入框永久顶掉

**两副面孔**：

1. **幽灵面板**：run 停在 ask_user 时，从另一个客户端把它停掉。引擎已是 `stopped`，本页面板 6 秒后还挂着「需要你确认 / 待回答」，composer 回不来。原因是 `pendingAsks` 只看 `q.status === 'pending'`，不看所属气泡是否已经收口。
2. **没有出口**：等待期间整个 composer 被面板替换，而「停止」按钮长在 composer 里——用户除了回答问题，没有任何叫停手段；服务端也没有提问超时。

**怎么修**：`pendingAsks` 只认「这一轮还没收口」的气泡（`streaming` / `offline`）；面板头加「停止」，调已有的 `stopCurrent()`（端点早就幂等）。

**验收**：面板里点停止 → 面板消失、输入框回来、气泡显示已停止；另开客户端停 → 本窗口 ≤3 秒弹回输入框。

## 4. P1：删掉的会话会留在侧栏

**病灶故事**：桌面端删掉一场会话，手机端（或另一个标签页）的侧栏还留着它；点进去是空白的「从一句话开始」，没有任何解释，条目也还在。

**为什么**：`session_deleted` 事件只做了「如果当前正打开它，就退回新对话」，没有把这条从 `recentSessions` 里摘掉；侧栏只在切会话/收尾时重拉。

**怎么修**：收到事件时顺手 filter 掉；不做全量重拉（重拉会把滚动位置和顺序打乱）。

**验收**：curl 删一条 → ≤3 秒侧栏消失；删当前会话 → 内容区和侧栏同时回到空态。

## 5. P1：新建同名内置助手会把内置配置清空

**病灶故事**：用户在「新建」里填了 `coder`（可能想改它的说明），保存成功——然后发现「coder」的说明、规格、工具策略全没了。实际上系统建了一条 override，并且用请求里的空串覆盖了从内置复制过来的值。

**为什么**：服务端「同名默认助手 → 建 override」是给**编辑内置**这条路用的（前端选中默认条目后走同一个 POST）；「新建」也走这条，于是空表单成了「清空」。

**怎么修**：前端在 `creating` 状态下先查两侧（root + subagent）的现有名字（含默认），撞名就**不发请求**，提示「要改它请在左侧选中后编辑」。服务端的 override 能力保留——编辑内置照旧。

**验收**：新建 `coder` → 横幅提示、override 条数不变；选中内置改说明 → 保存后是新写的那句。

## 6. P1：导入与新建的默认可见性相反

**病灶故事**：同一页面，手工新建的助手默认「仅自己」，导入的默认「团队可见」。导入的人通常以为只是自己多了一份，结果团队成员的助手列表里都出现了。

**为什么**：`importAgents` 里自定义行写死 `Visibility: "tenant"`，而前端新建写死 `private`。

**怎么修**：按拍板 Q2 统一（推荐「仅自己」），导入完成的提示里写明当前可见性。

**验收**：导入后 GET 的 `visibility` 是 `private`；改成团队可见后变 `tenant`。

## 7. P2：报错把网关语义塞给用户；被登出没有说明

**现象**：助手页导入重名显示 `409：这个名字已经有一份配置`；输错密码显示 `401：邮箱或密码不正确`；refresh token 失效时人直接被踢回登录页，屏幕上没有任何一句话。

**怎么修**：`show()` / `login()` 只显示 `message`；`clearAuth(reason)` 带上 `expired` 原因，登录表单据此显示「登录已过期，请重新登录」（主动退出不显示，登录成功即清除）。

**验收**：四处点一遍，文案里不含三位状态码；伪造 refresh token 后刷新 → 出现过期提示。

## 9. P2：名字没有边

项目名、助手名都没有长度上限：接口接受 100 字（前端也没有 `maxlength`），200 字也不拒。今天靠 CSS 兜住了布局，但会话标题、邀请页、审计导出都会用到这个名字。

**怎么修**：项目名 ≤100、助手名 ≤64（与 A1 同一条规则），服务端 400 `111002`，两处输入框 `maxlength`。

## 10. P3：自动链接吞掉中文标点

**现象**：模型输出 `https://example.com/a，后面`，链接把 `，` 编码进 href，点开是坏地址。

**怎么修**：`markdown.ts` 用 marked 的 `walkTokens`，自动链接末尾的全角标点（`，。、；：！？）》」』】`）从 href 与显示文本里剥掉；补一条 `npm test` 断言。

## 11. P3：项目页两句话与行为对不上

- 已经在默认项目里，仍显示「回到默认项目」，点了没反应 → 用已有 `isDefault` 控制显隐。
- 「新对话默认进入」读起来像一个可配置的默认值，实际是「上次在哪个项目」→ 按 Q3 改文案（推荐）或做成真设置。

## 12. P3：访问日志里有完整 access_token

**现象**：SSE 只能用查询串传 token（`EventSource` 没有自定义头），而 `gin.Default()` 的访问日志原样打印整条 URL——日志里躺着可用的凭证（有效期 15 分钟）。日志一旦进采集系统就等于外送。

**怎么修**：换成自定义 `LoggerWithFormatter`，把 `access_token=…` 打成 `***`，其余格式不变。**不改传参形态**（这是 EventSource 的唯一解）。

## 13. 明确不做

- **SSE 改用请求头**：EventSource 不支持；要用请求头就得换 fetch 流式实现，属于另一个方案。
- **静止标签页的 401 重连**：doc/48 已加「重连前先刷新 token」；页面静止时没有调用者仍是机制性限制。
- **ask_user 超时**：产品拍板项（多久算放弃、超时后 run 怎么收），本篇只补「人能停」。
- **新建同名内置助手在后端直接拒绝**：后端无法区分「编辑内置」与「新建撞名」（同一个 POST、同一形状），所以拦在前端。

## 16. 落地后补记（2026-10-24）

### #13 用户气泡里的行内代码白字白底，等于隐形

**现象**：用户发一条带反引号的消息（例：``第一行写 `## 标题`（两个井号）``），用户气泡（深色底）里那两个代码片段只剩一个米色圆角块，字完全看不见；同一段消息里的围栏代码块、表格、引用和链接是同一类问题，只是这条消息先暴露了行内代码。

**实测**（5173 页面，2026-10-24）：

```
CODE text="## 标题"
  color: rgb(246, 241, 231)   ← 继承 .bubble.user .bubble-main（App.vue:2531-2533）
  bg:    rgb(243, 240, 232)   ← .bubble-text :deep(code) 写死的 var(--bg)（App.vue:2581）
```

对比度 ≈1.0。根因是整套 markdown 排版（doc/48 A1）只按浅色助手气泡设计，用户气泡反过来是深底浅字。

**修复**：新增一组 `.bubble.user .bubble-text :deep(...)` 覆盖（code / pre / th / td / blockquote / a / hr），只把「浅底深字」的几项在深色气泡里翻过来；助手气泡不动。修复后实测行内代码 `fg=rgb(246,241,231)` / 合成底 `rgb(63,60,56)`，对比度 **9.8:1**。

**同类风险**：新配色（[doc/51](51-UI视觉重做.md)）会把用户气泡改到中性深墨，这组覆盖仍然成立；以后任何「深底气泡」都要先检查这七类元素。
