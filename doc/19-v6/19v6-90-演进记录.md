**初版定位（v6 立版）**：本文取代 v5。v6 = v5 的裁定结论 + 重写，不 copy v5 的篇幅。
只写第一步：跑通最小闭环所需的四个 API 的最简契约。骨架、组件、用例全集——不在内，后续 loop 各自成文。
**没有「明确不做」清单**：范围只在 §0 正面声明，其余一律「需要时照通道扩、不预留字段」。

**2026-10-02 二次修订（改纯拉模型）**：推翻「一条 message 所有 delta 同号」→ 每个 delta 独占 `eventOffset`；据此**删掉 SSE `stream` 端点，改为纯轮询拉取**（`runlive` 拉生成中的帧 + `runlog` 拉定稿历史）。理由：每 delta 独占号后 `eventOffset` 的唯一归宿就是续传游标，与其让流认游标或维护「挂流+拉取双路合并」，不如让 `runlive` 直接成为拉取端点、删掉流。无长连接、无推送、无 heartbeat。

**2026-10-02 三次修订（单批上限 + 初始游标窗口化）**：`runlog` 永久增长（compact 压的是 `model_history`，不动 `runlog`），所以「新 tab 游标 = 0 = 全量重拉」在长会话下是**无界请求**。改法**不加端点、不加索引、不加请求参数**：两个拉取端点统一加**单批上限 `W`**（`LRANGE key N N+W-1`），客户端初始游标改取 `max(0, 高水位 - 窗口)`——高水位本来就由 session 状态端点返回。又因 `runlogOffset` **永久有效**，往回拨游标翻更早的历史同样合法。

**2026-10-03 四次修订（REST 化端点形状）**：四个 API 的**路径**重排为资源式——
`POST /api/runs`（原 `/api/message`）、`GET /api/runs/{runId}/frames`（原 `/api/runlive`）、
`GET /api/sessions/{sessionId}`（原 `/api/session?id=`）、`GET /api/sessions/{sessionId}/log`（原 `/api/runlog?id=`）；
`202` 响应**新增 `runId`**。语义一字未动：懒建/准入、双游标、W、响应三态、`gone` 语义、
存储键名（`runlive:{runId}` / `runlog:{sessionId}` 等）全部原样。改名理由：`runlive`/`runlog` 只差三个字母，
正是「两种游标别混」的认知负担来源；新形状让双游标归属在 URL 上显式（run 内游标挂 frames，
session 全局游标挂 log），session 归属从 body/query 挪进 path。
**裁掉三个提出过但语义未设计的端点，不预留**：`GET /api/runs/{runId}`（frames 每批已带 `status`，冗余）、
`POST /api/runs/{runId}/cancel`（cancel 与 worker 收尾竞态、残缺 draft 去留均未设计，`stopped` 留它自己的
loop——届时加端点不改旧形状）、`GET /api/sessions`（列表的排序/分页/预览均未设计）。
原则：**没有用例逼出的端点不进契约**。

**2026-10-07 五次修订（闸租约化 + `tk:` 键名回填）**：19v6-03 的 `live:{sessionId}` 闸从「`SET NX` **不带 TTL**、
租约/reaper 留后续 loop」改为「**短 TTL 租约 + worker watchdog 续约**」——抢闸即 `SET NX PX <lease>`，
生成期间 watchdog 定期把 `live`/`draft`/`runlive` 三键的 TTL 同刷回 lease（**三键同生同灭**）；进程 `kill -9`
后没人续约，三键到点一起蒸发、会话**自动解锁**，无需 reaper 代跑收尾（客户端靠 19v6-02 的冗余收口信号
`gone` / `liveRunId:""` 自愈）。续约 Lua 带 **CAS**（闸仍等于本 run 才续），防网络分区复活的老 worker 给新 run 续命。
同时把 19v6-03 的键名回填为落地形态：全部带 **`tk:` 前缀**（reset 用 `SCAN tk:*` 对未来新键免疫，也是连错 Redis 实例时的误伤防线），
并补出 `model_history` 的 **Redis 形态 `tk:mh:{sessionId}`**（LIST，每项 `role`+`text`）。**四个 API 的线上字节零变化**。

**2026-10-07 六次修订（落库：三搬两留一消失）**：存储从「Redis 六键」搬到「**PG 四表 + Redis 两键**」——
`session`/`model_history`/`runlog` 落表（`sessions` / `runs` / `run_model_messages` / `runlog_entries`，四表同库），
`runlive`/`draft` 留 Redis（临时态，TTL 到即清、过期不影响历史正确性）；闸从 `live` 键的 `SET NX PX` 改为
`runs` 表 **`one_live_run_per_session` 部分唯一索引**（`WHERE status='running'`）——插入失败本身就是 409；
租约的真源从「三键 TTL 同生同灭」移到 `runs.lease_until` 列（watchdog 续约的 CAS = `UPDATE` 影响行数，
进程死亡 = 读侧即回收 + 新 POST 清扫死行翻 `error`）。`model_history` 与闸「同一笔原子写」从措辞变成事务边界：
放闸 `UPDATE` 与 assistant 行 `INSERT` 同一笔 PG 事务；`terminal` 帧仍由 commit 后的 Redis 半压入。
**四个 API 的线上字节零变化**（A4-1 baseline 原样重跑）。
