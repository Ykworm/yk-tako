# 19v6-04 · 验收（curl 手打）

> 本篇是 doc/19-v6 文档集的**验收篇**：用例 → curl 命令 → 期望字节。改契约字节必须同步改本篇期望并重跑。
> 端点契约真源在 `19v6-01`；游标语义在 `19v6-02`。
>
> **2026-10-21 校准**：本篇的 session 期望字节此前停在 doc/28 之前（只写 `liveRunId` + `runlogOffset`），
> 而实际响应自 doc/17 §4（`lastRunStatus`）、doc/30 A1（`lastRunId`）、doc/35 A4（`workspaceId`）起
> 已多三个字段——照旧字节断言会误判。现已按**现行代码**（`server.go` 的 `sessionResponse`）对齐。
> 同批把 `19v6-01` §2 的帧 kind 断言从五种改为七种（补 `usage` / `resume`），并同步 index 概念表与 doc/31。
>
> **校准的实跑实录（2026-10-21，8901，带登录态）**——上面两条 session 期望是打出来的，不是推的：
> ```
> # 投递（临时账号 + 已配租户模型）
> POST /api/runs  {"messageId":"m_v1","text":"只回复 ok"}
> → 202 {"sessionId":"s_01M5F21D10BJCYTAREND75N0B4","runId":"r_01M5F21D106HPH402DGBQETJTF","messageId":"m_v1"}
>
> # 跑中
> GET /api/sessions/s_01M5F21D10BJCYTAREND75N0B4
> → 200 {"liveRunId":"r_01M5F21D106HPH402DGBQETJTF","runlogOffset":1,"lastRunStatus":"running","lastRunId":"r_01M5F21D106HPH402DGBQETJTF","workspaceId":null}
>    字段序实测 = liveRunId → runlogOffset → lastRunStatus → lastRunId → workspaceId
>
> # 定稿后
> GET /api/sessions/s_01M5F21D10BJCYTAREND75N0B4
> → 200 {"liveRunId":"","runlogOffset":2,"lastRunStatus":"complete","lastRunId":"r_01M5F21D106HPH402DGBQETJTF","workspaceId":null}
>
> # frames（含 usage 帧——第 6 种 kind 的实锤）
> GET /api/runs/r_01M5F21D106HPH402DGBQETJTF/frames?eventOffset=0
> → 200 {"frames":[
>      {"eventOffset":1,"kind":"start","agent":"","model":"","messageId":"m_v1"},
>      {"eventOffset":2,"kind":"delta","agent":"","model":"deepseek/deepseek-flash","text":"ok"},
>      {"eventOffset":3,"kind":"usage","agent":"","model":"deepseek/deepseek-flash","promptTokens":3932,"completionTokens":2,"totalTokens":3934,"window":256000},
>      {"eventOffset":4,"kind":"terminal","agent":"","model":"","status":"complete"}
>    ],"nextOffset":4,"status":"done"}
> ```
> **`resume` 帧**没有出现在这次实录里——它只在**崩溃后接管**那条路径上产生（doc/30 §8.3），
> 它的字节与验收见 doc/30，不在本篇矩阵内。改动契约字节后必须重跑本篇。

> **2026-10-21 补：doc/28 之后的认证前置。** 自 doc/28 起，本篇的四个业务端点全部挂 `RequireAuth`——
> 下面用例里的 curl **每一条都要带 `-H "Authorization: Bearer $TOK"`**，否则一律 401。
> 补录一段实测（2026-10-21，引擎 8943/8944、隔离库、Redis db 7）：
> ```
> # 无 Authorization：四个端点同形
> POST  /api/runs              → 401 {"code":111102,"message":"请先登录","data":null}
> GET   /api/sessions/{id}     → 401 {"code":111102,"message":"请先登录","data":null}
> GET   /api/runs/{id}/frames  → 401 {"code":111102,"message":"请先登录","data":null}
> GET   /api/sessions/{id}/log → 401 {"code":111102,"message":"请先登录","data":null}
>
> # 带登录态：业务端点仍是旧体（不带信封）
> POST /api/runs              → 202 {"sessionId":"s_01…","runId":"r_01…","messageId":"m_1"}
> GET  /api/sessions/{id}     → 200 {"liveRunId":"r_01…","runlogOffset":1,"lastRunStatus":"running","lastRunId":"r_01…","workspaceId":null}
> GET  /api/runs/{id}/frames  → 200 {"frames":[…],"nextOffset":33,"status":"done"}
> GET  /api/sessions/{id}/log → 200 {"rows":[…],"nextOffset":2}
>
> # 忙时拒绝（第一场还在跑时）
> POST /api/runs {"sessionId":"s_01","messageId":"m_2"} → 409 {"error":"session_busy"}，runlog 行数不变
> ```
> **体例分界**：auth 端点用 `{code,message,data}` 信封；**四个业务端点仍是旧体**（不带信封）——
> 旧成功体换信封是 doc/28 A7 那一档，不在本篇范围。

```
# ═══ 用例 0：认证与前置（doc/28 起，下面每个用例都依赖它）═══
# 业务四端点自 doc/28 起全部挂 RequireAuth：不带 Authorization 一律 401 信封体。
# 注意体例分界——auth 端点用 {code,message,data} 信封；四个业务端点仍是旧体（不带信封）。

curl -X POST localhost:8080/api/auth/signup -d '{"email":"you@example.com","password":"changeme123"}'
→ 201 {"code":0,"message":"","data":{"user":{"id":"u_01","email":"you@example.com"},"tenant":{"id":"t_01","kind":"personal","name":"you"},"membership":{"tenantId":"t_01","role":"owner"},"accessToken":"…","tokenType":"Bearer","expiresIn":900,"refreshToken":"…"}}
   把 accessToken 放进 $TOK（下文每个 curl 都带 -H "Authorization: Bearer $TOK"）。

# 租户模型：租户没配模型密钥时，POST /api/runs 回 409 {"code":111408,"message":"这个工作区的模型还不可用","data":null}，run 根本起不来。
curl -X PUT localhost:8080/api/tenants/$TID/runtime-config -H "Authorization: Bearer $TOK" \
  -d '{"modelRef":"deepseek/deepseek-flash","mcpServers":{},"secrets":{"DEEPSEEK_API_KEY":"sk-…"},"sandbox":{"network":false}}'
→ 200 {"code":0,"message":"","data":{"config":{…,"secrets":{"DEEPSEEK_API_KEY":"••••"}}}}   （密钥回显成掩码）

# ═══ 用例 1：投递 → 轮询看生成 → 定稿看历史 ═══
curl -X POST localhost:8080/api/runs -H "Authorization: Bearer $TOK" -d '{"messageId":"m_1","text":"hi"}'
→ 202 {"sessionId":"s_01","runId":"r_01","messageId":"m_1"}          （旧体，不带信封）

curl localhost:8080/api/sessions/s_01 -H "Authorization: Bearer $TOK"
→ 200 {"liveRunId":"r_01","runlogOffset":1,"lastRunStatus":"running","lastRunId":"r_01","workspaceId":null}
                                               （刚开跑，user 已进 runlog）

curl 'localhost:8080/api/runs/r_1/frames?eventOffset=0' -H "Authorization: Bearer $TOK"   （反复轮询，frames 逐次变长）
→ frames: [start] → [start,delta,delta] → […,usage,terminal], status: generating→done

curl localhost:8080/api/sessions/s_01 -H "Authorization: Bearer $TOK"
→ 200 {"liveRunId":"","runlogOffset":2,"lastRunStatus":"complete","lastRunId":"r_01","workspaceId":null}
                                               （定稿后）

curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=0' -H "Authorization: Bearer $TOK"
→ rows:[{1,user,"hi"},{2,assistant,"…全文"}], nextOffset:2

# ═══ 用例 2：游标增量 & 越界 ═══
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=1' -H "Authorization: Bearer $TOK"   → 只 offset>1
curl 'localhost:8080/api/runs/r_1/frames?eventOffset=999' -H "Authorization: Bearer $TOK" → {"frames":[],"nextOffset":999,"status":"generating"}
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=999' -H "Authorization: Bearer $TOK" → {"rows":[],"nextOffset":999}

# ═══ 用例 3：带未知 sessionId / 未知 run ═══
curl -X POST localhost:8080/api/runs -H "Authorization: Bearer $TOK" -d '{"sessionId":"s_nope","messageId":"m_9","text":"hi"}'
→ 404 {"error":"session_not_found"}          （旧体）
curl localhost:8080/api/sessions/s_nope -H "Authorization: Bearer $TOK"
→ 404 {"error":"session_not_found"}
curl localhost:8080/api/sessions/s_nope/log -H "Authorization: Bearer $TOK"
→ 404 {"error":"session_not_found"}
curl 'localhost:8080/api/runs/r_nope/frames' -H "Authorization: Bearer $TOK"
→ 200 {"frames":[],"nextOffset":0,"status":"gone"}   （未知 run 不是 404——19v6-01 §0）

# ═══ 用例 4：忙时诚实拒绝 ═══
（会话有活 run 时）curl -X POST localhost:8080/api/runs -H "Authorization: Bearer $TOK" -d '{"sessionId":"s_01","messageId":"m_2","text":"急"}'
→ 409 {"error":"session_busy"}（旧体），且 runlog/runlive 里没有 m_2 的任何痕迹（忙拒后 runlog 行数不变）

# ═══ 用例 5：单批上限 W（W=200 时造不出截断，dev 起服务把它调小：-batch-window 3）═══
（runlog 已有 5 条时）
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=0' -H "Authorization: Bearer $TOK"  → 只返回 offset 1..3，nextOffset:3
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=3' -H "Authorization: Bearer $TOK"  → 返回 offset 4..5，nextOffset:5
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=5' -H "Authorization: Bearer $TOK"  → {"rows":[],"nextOffset":5}
# 往回拨（翻页游标）同样合法：
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=1' -H "Authorization: Bearer $TOK"  → 返回 offset 2..4（受 W=3 限），nextOffset:4
# frames 端点同一条规则（2026-10-21 实测，引擎 -batch-window 3）：
curl 'localhost:8080/api/runs/r_1/frames?eventOffset=0' -H "Authorization: Bearer $TOK"   → offset 1..3，nextOffset:3
curl 'localhost:8080/api/runs/r_1/frames?eventOffset=3' -H "Authorization: Bearer $TOK"   → offset 4..6，nextOffset:6
curl 'localhost:8080/api/runs/r_1/frames?eventOffset=24' -H "Authorization: Bearer $TOK"  → 末批 offset 25..26（usage,terminal），nextOffset:26
# 客户端必须跟着 nextOffset 走：只拉 eventOffset=0 那一批，永远看不到后面的 terminal。

# ═══ 用例 6：工具循环（get_time）——tool 帧 / runlog 扩展行 / 跨 run 记忆 ═══
curl -X POST localhost:8080/api/runs -H "Authorization: Bearer $TOK" -d '{"messageId":"m_1","text":"现在几点"}'
→ 202 {"sessionId":"s_01","runId":"r_01","messageId":"m_1"}      （记下 s_01）

curl 'localhost:8080/api/runs/r_01/frames?eventOffset=0' -H "Authorization: Bearer $TOK"           （反复轮询）
→ frames 序列：start → tool_call → tool_result → delta… → terminal；tool 帧夹在 delta 之间，顺序即事件序：
  {"eventOffset":2,"kind":"tool_call","agent":"","model":"deepseek/deepseek-flash","name":"get_time","args":"{\"timezone\":\"Asia/Shanghai\"}"}
  {"eventOffset":3,"kind":"tool_result","agent":"","model":"deepseek/deepseek-flash","name":"get_time","output":"2026-10-08 15:04:05 +0800 CST"}
  每帧带 agent（空 = root，含 start/terminal）与 model（生效 ref；start/terminal 为空——19v6-01 §2）

curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=0' -H "Authorization: Bearer $TOK"
→ rows：user(model:"") → tool_call(text:"get_time(…)",payload 非空) → tool_result(text:输出原文,payload 非空) → assistant(全 run delta 累计全文)
  每行带 agent 与 model（user 行 model 空、root 行 model = 主 ref）；assistant 行仍是收口替换的锚

# 跨 run 记忆（mh 是模型输入的实证）：带 sessionId 再投，模型应凭上一轮的 tool 行接上文
curl -X POST localhost:8080/api/runs -H "Authorization: Bearer $TOK" -d '{"sessionId":"s_01","messageId":"m_2","text":"我刚才问的几点"}'
→ 新一轮正常生成：回复应复述刚才的时间（也可能再调一次 get_time 刷新——两种都算过；
  判据是模型没答「我没查过/不知道」——它看得见历史里的 assistant(tool_calls)+tool 两行）

# ═══ 用例 7：委派（sub agent）——子代理帧/行 + 回传裁剪（机制 19v6-05 §4）═══
# 起服务把回传帽调小演示裁剪（默认 51200 B 太大难现裁；同用例 5 的 W 先例）：
#   go run ./cmd/yktako -engine 127.0.0.1:<port> -subagent-return-cap 2000
#   启动日志：subagents: concurrency N, return cap 2000 B；每次 run 起手：agents: <N> spec(s): researcher

curl -X POST localhost:<port>/api/runs -H "Authorization: Bearer $TOK" -d '{"messageId":"m_7","text":"请委派 researcher 写一份分析报告：<具体题材>；一次性直接输出完整全文，不要分多轮——只为逼出超帽回传"}'
→ 202 {"sessionId":"s_01","runId":"r_01","messageId":"m_7"}

curl 'localhost:<port>/api/runs/r_01/frames?eventOffset=0' -H "Authorization: Bearer $TOK"          （反复轮询）
→ 帧序（顺序即事件序）：
  start → root delta… → {"kind":"tool_call","agent":"","model":"<主 ref>","name":"researcher","args":"<委派任务原文>"}
  → 子代理帧流：{"kind":"delta","agent":"researcher","model":"<该规格生效 ref>","text":"…"}
    （子代理自调工具时，其 tool_call/tool_result 帧同带 agent:"researcher" 与生效 ref）
  → {"kind":"tool_result","agent":"","model":"<主 ref>","name":"researcher","output":"<回传文本>"} → root delta… → terminal{complete}
  回传超帽时 output 尾部带尾缀（原文）：[Output truncated: N bytes omitted. Full output preserved in subagent runlog.]

curl 'localhost:<port>/api/sessions/s_01/log?runlogOffset=0' -H "Authorization: Bearer $TOK"
→ 行序（消息粒度；每行 agent/model 恒在）：
  user → tool_call(agent:"",text:"researcher({…})") → [agent:"researcher" 的行：其工具活动扩展行 + 终稿 assistant 行（全量）]
  → tool_result(agent:"",text:已裁剪回传) → assistant(agent:"",text:主线程终稿)
  裁剪断言（先裁后落，19v6-05 §4）：回传文本 = 子代理终稿行的字节前缀（≤ cap 字节、截点回退到 UTF-8 rune 边界）
  + 尾缀，N = 终稿总字节 − 保留字节（对得上）——模型侧有界（回传/mh 已裁）、审计侧无损（子代理终稿行全文）
  尾缀里的「subagent runlog」= 本端点里 agent:"researcher" 的行（无新端点；客户端按行内 agent 字段跳转）
  多调用并存（同轮委派 + 其他工具）时行序 = 事件到达序：委派块与其他调用块可能交错，
  客户端逐行看 agent/model 即可归属（不做树形重排）
