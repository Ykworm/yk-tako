# 19v6-04 · 验收（curl 手打）

> 本篇是 doc/19-v6 文档集的**验收篇**：用例 → curl 命令 → 期望字节。改契约字节必须同步改本篇期望并重跑。
> 端点契约真源在 `19v6-01`；游标语义在 `19v6-02`。

```
# 用例 1：投递 → 轮询看生成 → 定稿看历史
curl -X POST localhost:8080/api/runs -d '{"messageId":"m_1","text":"hi"}'
→ 202 {"sessionId":"s_01","runId":"r_01","messageId":"m_1"}

curl localhost:8080/api/sessions/s_01
→ 200 {"liveRunId":"r_01","runlogOffset":1}          （刚开跑，user 已进 runlog）

curl 'localhost:8080/api/runs/r_1/frames?eventOffset=0'   （反复轮询，frames 逐次变长）
→ frames: [start] → [start,delta,delta] → [...,terminal], status: generating→done

curl localhost:8080/api/sessions/s_01
→ 200 {"liveRunId":"","runlogOffset":2}             （定稿后）

curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=0'
→ rows:[{1,user,"hi"},{2,assistant,"…全文"}], nextOffset:2

# 用例 2：游标增量 & 越界
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=1'   → 只 offset>1
curl 'localhost:8080/api/runs/r_1/frames?eventOffset=999' → {"frames":[],"nextOffset":999,...}
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=999' → {"rows":[],"nextOffset":999}

# 用例 3：带未知 sessionId
curl -X POST localhost:8080/api/runs -d '{"sessionId":"s_nope","messageId":"m_9","text":"hi"}'
→ 404 {"error":"session_not_found"}

# 用例 4：忙时诚实拒绝
（会话有活 run 时）curl -X POST localhost:8080/api/runs -d '{"sessionId":"s_01","messageId":"m_2","text":"急"}'
→ 409 {"error":"session_busy"}，且 runlog/runlive 里没有 m_2 的任何痕迹

# 用例 5：单批上限 W（W=200 时造不出截断，dev 起服务把它调小：-batch-window 3）
（runlog 已有 5 条时）
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=0'  → 只返回 offset 1..3，nextOffset:3
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=3'  → 返回 offset 4..5，nextOffset:5
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=5'  → {"rows":[],"nextOffset":5}
# 往回拨（翻页游标）同样合法：
curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=1'  → 返回 offset 2..4（受 W=3 限），nextOffset:4

# 用例 6：工具循环（get_time）——tool 帧 / runlog 扩展行 / 跨 run 记忆
curl -X POST localhost:8080/api/runs -d '{"messageId":"m_1","text":"现在几点"}'
→ 202 {"sessionId":"s_01","runId":"r_01","messageId":"m_1"}      （记下 s_01）

curl 'localhost:8080/api/runs/r_01/frames?eventOffset=0'           （反复轮询）
→ frames 序列：start → tool_call → tool_result → delta… → terminal；tool 帧夹在 delta 之间，顺序即事件序：
  {"eventOffset":2,"kind":"tool_call","agent":"","model":"deepseek/deepseek-flash","name":"get_time","args":"{\"timezone\":\"Asia/Shanghai\"}"}
  {"eventOffset":3,"kind":"tool_result","agent":"","model":"deepseek/deepseek-flash","name":"get_time","output":"2026-10-08 15:04:05 +0800 CST"}
  每帧带 agent（空 = root，含 start/terminal）与 model（生效 ref；start/terminal 为空——19v6-01 §2）

curl 'localhost:8080/api/sessions/s_01/log?runlogOffset=0'
→ rows：user(model:"") → tool_call(text:"get_time(…)",payload 非空) → tool_result(text:输出原文,payload 非空) → assistant(全 run delta 累计全文)
  每行带 agent 与 model（user 行 model 空、root 行 model = 主 ref）；assistant 行仍是收口替换的锚

# 跨 run 记忆（mh 是模型输入的实证）：带 sessionId 再投，模型应凭上一轮的 tool 行接上文
curl -X POST localhost:8080/api/runs -d '{"sessionId":"s_01","messageId":"m_2","text":"我刚才问的几点"}'
→ 新一轮正常生成：回复应复述刚才的时间（也可能再调一次 get_time 刷新——两种都算过；
  判据是模型没答「我没查过/不知道」——它看得见历史里的 assistant(tool_calls)+tool 两行）

# 用例 7：委派（sub agent）——子代理帧/行 + 回传裁剪（机制 19v6-05 §4）
# 起服务把回传帽调小演示裁剪（默认 51200 B 太大难现裁；同用例 5 的 W 先例）：
#   go run ./cmd/yktako -engine 127.0.0.1:<port> -subagent-return-cap 2000
#   启动日志：subagents: concurrency N, return cap 2000 B；每次 run 起手：agents: <N> spec(s): researcher

curl -X POST localhost:<port>/api/runs -d '{"messageId":"m_7","text":"请委派 researcher 写一份分析报告：<具体题材>；一次性直接输出完整全文，不要分多轮——只为逼出超帽回传"}'
→ 202 {"sessionId":"s_01","runId":"r_01","messageId":"m_7"}

curl 'localhost:<port>/api/runs/r_01/frames?eventOffset=0'          （反复轮询）
→ 帧序（顺序即事件序）：
  start → root delta… → {"kind":"tool_call","agent":"","model":"<主 ref>","name":"researcher","args":"<委派任务原文>"}
  → 子代理帧流：{"kind":"delta","agent":"researcher","model":"<该规格生效 ref>","text":"…"}
    （子代理自调工具时，其 tool_call/tool_result 帧同带 agent:"researcher" 与生效 ref）
  → {"kind":"tool_result","agent":"","model":"<主 ref>","name":"researcher","output":"<回传文本>"} → root delta… → terminal{complete}
  回传超帽时 output 尾部带尾缀（原文）：[Output truncated: N bytes omitted. Full output preserved in subagent runlog.]

curl 'localhost:<port>/api/sessions/s_01/log?runlogOffset=0'
→ 行序（消息粒度；每行 agent/model 恒在）：
  user → tool_call(agent:"",text:"researcher({…})") → [agent:"researcher" 的行：其工具活动扩展行 + 终稿 assistant 行（全量）]
  → tool_result(agent:"",text:已裁剪回传) → assistant(agent:"",text:主线程终稿)
  裁剪断言（先裁后落，19v6-05 §4）：回传文本 = 子代理终稿行的字节前缀（≤ cap 字节、截点回退到 UTF-8 rune 边界）
  + 尾缀，N = 终稿总字节 − 保留字节（对得上）——模型侧有界（回传/mh 已裁）、审计侧无损（子代理终稿行全文）
  尾缀里的「subagent runlog」= 本端点里 agent:"researcher" 的行（无新端点；客户端按行内 agent 字段跳转）
  多调用并存（同轮委派 + 其他工具）时行序 = 事件到达序：委派块与其他调用块可能交错，
  客户端逐行看 agent/model 即可归属（不做树形重排）
```
