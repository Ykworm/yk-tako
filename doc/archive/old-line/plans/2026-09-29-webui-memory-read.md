# Web UI：页面读内存列表，模型读已完成消息

> 按本计划逐项实现。做完一项就把该条 `- [ ]` 改成 `- [x]`。
> 对话里定下的读法，落在现有两张表上，不新开消息表，不接 Redis。

**目标：** 页面按序号读进程内的事件列表，读走不删。列表没有这场 run 时，从 `event_log` 装回来再读。模型下一轮只读档案里已经写上产出的轮次，不再另留一份 `session.history`。

**不做：** Redis、运行中插话、完成时删列表、在途审批跨重启续跑。

**续（逐字、半截、补发）：** 助手正文按字进入内存并推给页面，同一序号反复更新，写完才进 SQLite。模型流出失败时，这半截标成失败，不落库，读者读到后从内存删掉。页面把已写完的正文记在浏览器本地；服务重启后若库里没有这一条，浏览器把它补回去。

## 续任务

- [x] **任务 6：逐字流出**

  Web 的 runner 打开流式。助手正文每多一块字，就更新内存里同一条事件并推给正在看的页面。工具调用和工具结果仍是写完的一整条。

- [x] **任务 7：半截不落库**

  这条正文在写完之前不进 SQLite。写完后按已经分配的序号落库。模型中途出错，内存里标失败，不落库；读者拿到失败帧之后，从内存删掉这半截。

- [x] **任务 8：浏览器补发**

  页面收到写完的正文后记在 localStorage。打开页面时交给服务。库里已有这条就不动。库里没有、且这轮不在跑，就按原序号补上，并让下一轮模型读得到这句。

  > **注（2026-09-30）**：本任务记录的浏览器补发做法已被 `doc/15-页面从event_log读对话的实施计划.md` 接替。新读法下，已结束的对话按会话从 `event_log` 懒加载，Chrome 不再保存助手正文，`POST /api/chat/restore` 不再被页面调用。

- [x] **任务 9：测试与格式**

  多块字的流出在结束前库里看不到正文。结束后库里只有一条。失败的半截不在库里。补发能把缺失的正文写回。`gofmt -l .` 为空，`go test -race ./internal/webui/ ./internal/adkrun/` 通过。

## 任务

- [x] **任务 1：内存列表**

  进程内按 run 保留已落库的事件，按 seq 追加，相同 seq 不重复。`From` 返回序号大于给定值的副本，不删除。seq 为 1 的 `start` 放进来时，这场列表即为可读。重启后列表是空的，第一次读把库里该 run 的全部事件装入，再按序号读。

- [x] **任务 2：读者改读内存**

  `writeEvents` 不再直接轮询 `event_log`。先读内存；内存还没有这场 run，就装库再读。终局判断仍看档案状态。`BeginRun`、`Append`、`Finish` 成功后把带序号的那一帧放进内存。

- [x] **任务 3：模型读已完成的档案**

  去掉 `session.history`。开一轮时按 `created_at` 读本会话 `status = completed` 且 `produced_json` 非空的行：每行是用户消息加上这轮产出。失败、停止、对账成 `failed` 的轮次没有产出，不进入下一轮。

- [x] **任务 4：测试**
