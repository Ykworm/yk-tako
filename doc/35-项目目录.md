## 0. 已拍的六条

开工时前五条按推荐项生效。第 2 条、第 5 条在 2026-10-20 重拍。第 6 条同一天补上。

1. 挂在同一个项目上的所有会话，共用一个物理目录 `tenants/<tid>/workspaces/<wid>/`。A 会话的 agent 写下的文件，B 会话的 agent 在同一路径读得到。
2. 附件永远挂 workspace。目标工作区是会话行上的 `workspace_id`；这一列为空时，落到第 6 条的默认工作区。字节在 `tenants/<tid>/workspaces/<wid>/.media/<sha16>.<ext>`，占位 path 是 `workspaces/<wid>/.media/<sha16>.<ext>`。取图和模型读图按这个工作区的可见性查，复用 `VisibleWorkspace`。图跟着容器走：项目是 `tenant`，同租户成员取得到图；项目或默认工作区是 `private`，只有属主取得到。会话自己的 `visibility` 不决定这张图谁能取。agent 的工作产出仍按今天的规则：挂了项目进项目目录，没挂进会话目录。存量 `sessions/<sid>/.media/` 清掉，旧占位 path 直接 404，不做两套路径并存。施工分成三拍，三拍都已写。A8a 做默认工作区，以及「会话和这次请求都没有项目」时入口图的字节目录。A8b 把占位 path、`getMedia`、已经挂上项目的入口图换到工作区。A8c 让模型按工作区读图，并在进程启动时清掉 `sessions/<sid>/.media/`。
3. 删除只删空项目。项目下还有会话时回 409，先把会话挪走。空项目删表行，并递归删掉项目目录。连带删会话另立拍。默认工作区即使下面没有会话也不能删，见第 6 条。2026-10-21 [doc/37](37-删除与档案清理.md) 已落地，本条里「项目下还有会话时回 409」和「连带删会话另立拍」不再作施工依据：有会话改为连带软删，`114002` 退役；项目下有活 run 回 `114006`，删单场会话遇到活 run 回 `114007`。
4. 项目默认只有创建者能看、能改名、能删。表上有 `visibility`，取值 `private` 或 `tenant`，新建和存量都是 `private`。创建者把它改成 `tenant` 之后，同租户成员用 `GET /api/workspaces?scope=tenant` 能看见，并能不带 `sessionId` 新开自己的会话，作业根是项目目录。会话自己的 `visibility` 仍是 `private`。项目改回 `private` 后，成员再往已挂上的会话发消息，回 404，code `114001`，不建 run，列先留着。创建者自己的会话不受这次收回的影响。创建者用 `GET /api/sessions?workspaceId=` 列自己的项目时，能看见别人挂上的会话，并能把它们解绑。不能把别人的会话改挂到别的项目，也读不到对方的正文。
5. `POST /api/runs` 不带 `workspaceId` 就是不挂项目。产出文件仍在会话目录。这场会话的附件落到默认工作区。「游离」只描述产出文件的作业根。存量会话不迁移。项目是可选项。
6. 每个（租户，用户）有一个私有默认工作区。`workspaces.is_default` 为 true 时，部分唯一索引 `(tenant_id, user_id) WHERE is_default` 保证这一对至多一行。插入冲突就是闸，闸在库里。id 仍是随机的 `ws_`，名字是「默认」，`visibility` 是 `private`。创建、列表、改名和普通项目相同，列表响应里不额外露出 `is_default`。它特殊的两处：解析附件目标时，会话和这次请求都没有项目，就用这一行，没有就当场建；`DELETE` 回 HTTP 409 `{"code":114005,"message":"默认工作区不能删除","data":null}`，行不删，目录不删。注册时不建这行。纯文本的游离 run 也不建。同租户的另一个用户有自己的一行，默认列表互相看不见。团队里不设「全员共用的一个默认工作区」，否则一个人的私人附件会进所有成员的眼。

## 1. 背景与动机

doc/28 落地之后，一个租户看不到另一个租户的会话和文件。同一个租户里面，文件仍按一场会话一个目录隔开。agent 的文件工具根是 `tenants/<tid>/sessions/<sid>/`。

用户在租户 `t_acme` 里做「Q4 调研」，连开三场会话。第一场让 agent 写下 `中间产物.md`。第二场想接着改，agent 调用 `read_file("中间产物.md")` 失败：文件根是第二场自己的目录，第一场的文件在隔壁 `sessions/<sid>/` 里。用户只能把内容复制过去。一个月后想把这几场翻出来继续，会话列表是平铺的，哪几场属于哪件事只能靠标题回忆。

tenant 管租户之间的隔离，session 管一场对话。中间缺的那一层，是同一件事的多场对话，加上它们共用的文件。这一层叫项目，表名 `workspaces`。

项目是 tenant 下的一行表记录，外加一个目录。表管归属和名字，目录管字节。会话挂进项目后，这场 run 的 agent 以项目目录为工作根。没挂的会话，包括全部存量，维持现状。「按项目切换」是每次请求自己带 `workspaceId` 做筛选。当前看哪个项目，由前端记住。多副本下服务端不保存「我正在看哪个项目」。

## 2. 名词

- **项目（workspace）**：`workspaces` 表一行。`id` 以 `ws_` 开头，后面是 ULID。列还有 `tenant_id`、`user_id`（创建者）、`name`、`visibility`、`is_default`、`created_at`。`visibility` 是 `private` 或 `tenant`。`is_default` 为 true 的那一行是第 0 节第 6 条的默认工作区。磁盘路径是 `<workspace>/tenants/<tid>/workspaces/<wid>/`。`<workspace>` 是启动参数 `-workspace`，沿用现义，不改这个参数的名字。
- **作业根**：一场 run 里，agent 的文件工具和 bash 的工作目录。今天是 `tenants/<tid>/sessions/<sid>/`。挂上项目之后是 `tenants/<tid>/workspaces/<wid>/`。
- **游离会话**：`sessions.workspace_id` 为 NULL 的会话。全部存量会话都是游离的。以后建会话时不传 `workspaceId`，也是游离的。这个词只描述作业根。附件另有归属，见第 0 节第 2 条。
- **默认工作区**：当前租户里、当前用户名下、`is_default` 为 true 的那一行项目。没有这行时，第一次要给游离会话落附件才会建。
- **active tenant**：access token 里的 `tid`。`POST /api/auth/switch-tenant` 切换它。新建项目挂在这个租户下。

A1 只插入表行，不建磁盘目录。目录在 A3：worker 起一场已经挂上项目的 run 时创建。一个项目如果还没有任何 run，盘上可以还没有 `workspaces/<wid>/`。A6 删除时空目录不存在，`RemoveAll` 也算成功。

## 3. 用户原话怎么落

| 用户原话 | 落法 |
|---|---|
| 系统支持多 tenant | 现状已有（doc/28），本篇不动 |
| tenant 下面每个 user 能建多个项目目录 | `workspaces` 带 `tenant_id` 和 `user_id`。`POST /api/workspaces` |
| session 挂到某个项目下 | `sessions` 加可空列 `workspace_id`。`POST /api/runs` 的请求体加可选 `workspaceId` |

## 4. 端到端链路

用户注册或登录，token 带上 active tenant。

1. `POST /api/workspaces`，body 是 `{"name":"Q4 调研"}`。服务端用 token 的 tenant 和 user 插入一行，回 201。这一跳是 A1，代码已经写上。
2. `POST /api/runs` 带 `workspaceId`。请求字段是 `text`，不是 `input`。`postRuns` 先确认这个项目当前用户看得见：自己创建的，或本租户 `visibility=tenant` 的。对不上则 404，code `114001`，不建 run。对得上，新会话仍由服务端铸 `sessionId`（请求里不带这个字段）。`AcquireRun` 只在插入新 `sessions` 行时写下 `workspace_id`，写入前锁的是看得见的项目行。请求里带了未登记的 `sessionId`，仍是 404 `{"code":112001,"message":"找不到这场会话","data":null}`，不建行。已有会话再带 `workspaceId` 也不改这一列，挪进挪出走 A5 的 PATCH。下一场 run 的作业根看的是库里的列，不看这次请求。已经挂上的会话再发消息时，按这一列再看一次项目；成员已经看不见，同样 114001，不建 run。
3. worker 起 run，读 session 行的 `workspace_id`。有值，作业根是 `tenants/<tid>/workspaces/<wid>/`。没有值，作业根仍是 `tenants/<tid>/sessions/<sid>/`。
4. agent 调用 `write_file("中间产物.md")`，字节落在项目目录。同一项目的另一场会话再 `read_file("中间产物.md")`，读得到。
5. `GET /api/sessions?workspaceId=ws_x` 只返回挂在这个项目上的会话。不带这个参数时，返回这个用户能看到的全部会话，含游离的。
6. `PATCH /api/sessions/:id`，body `{"workspaceId":""}`，把会话解绑。`{"workspaceId":"ws_x"}` 则挂上去。解绑之后，已经写在项目目录里的文件留在原地。下一场 run 的作业根跟着新的归属走。
7. 项目下已经没有会话时，`DELETE /api/workspaces/ws_x` 删掉表行，并递归删掉目录。成功是 HTTP 200 `{"code":0,"message":"","data":{"status":"deleted"}}`。还有会话则 409，code `114002`。会话行不删。

链路可以点名：用户 → `postWorkspaces` 或 `postRuns`（`server.go`）→ `AcquireRun`（`store.go`）→ worker 起 run 时调用 `runWorkspace`（`worker.go`）→ `scope.go` 的目录解析 → `listSessions`。挪进挪出走 `patchSessionWorkspace` → `SetSessionWorkspace`。删空项目走 `deleteWorkspace` → `DeleteWorkspace`，提交之后 `RemoveAll`。A1 到 A6 已经接通。入口图在 `postRuns` 里先走 `imageRoot`。已有会话只看会话行上的项目；新会话看这次请求的 `workspaceId`。两边都空时，`EnsureDefaultWorkspace` 取出或建出默认工作区。字节写到 `workspaces/<wid>/.media/`，占位 path 是 `workspaces/<wid>/.media/<sha16>.<ext>`。登录后的 `GET /api/media` 先 Clean 这条 path，再按 `VisibleWorkspace` 决定能不能读。看不见回 404 `{"code":114001,"message":"找不到这个项目","data":null}`（2026-10-22 换信封，见 [doc/40](40-响应信封统一.md)）。`read_media_file` 用同一条 path：先查 `VisibleWorkspace`，再从租户根下的 `workspaces/<wid>/` 读。回执带 size 和 sha，不带图字节。`sessions/<sid>/...` 读不到。进程启动时删掉各租户 `sessions/<sid>/.media/`，工作区里的 `.media` 不动。dev 探针继续用会话目录。

## 6. A1 契约：POST /api/workspaces

调用者是已登录用户。路由挂 `RequireAuth`。归属不从 body 取：`tenant_id` 用 token 的 `tid`，`user_id` 用 token 的 `sub`。

```http
POST /api/workspaces
Authorization: Bearer <accessToken>
Content-Type: application/json

{"name":"Q4 调研"}
```

成功是 HTTP 201。字段顺序是 `code`、`message`、`data`，项目对象里是 `id`、`name`、`createdAt`：

```json
{"code":0,"message":"","data":{"workspace":{"id":"ws_…","name":"Q4 调研","createdAt":"2026-10-19T12:00:00.123456+08:00"}}}
```

`createdAt` 是 Go `time.Time` 的 RFC3339。响应不带回 `tenantId` 和 `userId`，这两列只在表里。同名项目可以有多行，名字不是唯一键。这一拍不建磁盘目录。

名字先去掉首尾空白。去掉之后是空字符串，HTTP 400：

```json
{"code":114003,"message":"请填写项目名称","data":null}
```

请求体不是 JSON，HTTP 400，code `111001`，message 是「请求格式不对」。

没带 token，HTTP 401：

```json
{"code":111102,"message":"请先登录","data":null}
```

插入失败，HTTP 500，code `111901`，message 是「服务暂时不可用，请再试一次」。具体错误只进服务端日志。

## 7. 后面几拍的契约

A2 到 A6 已经按下面的形状写进代码。

**A2 列表。** `GET /api/workspaces`。条件是 `tenant_id` 等于 active tenant，并且 `user_id` 等于当前用户。按 `created_at`、再按 `id` 升序。没有项目时 `workspaces` 是空数组，不是 `null`。成功是 HTTP 200：

```json
{"code":0,"message":"","data":{"workspaces":[{"id":"ws_…","name":"Q4 调研","createdAt":"…"}]}}
```

同租户的另一个用户看到的是 `{"code":0,"message":"","data":{"workspaces":[]}}`。他后来自己建的项目只出现在他自己的列表里。

**A2 改名。** `PATCH /api/workspaces/:id`，body `{"name":"…"}`。名字的空白规则和创建相同，空名称仍是 HTTP 400，code `114003`。只有创建者能改。成功是 HTTP 200，体和创建一样，`createdAt` 不变：

```json
{"code":0,"message":"","data":{"workspace":{"id":"ws_…","name":"Q4 调研（改）","createdAt":"…"}}}
```

别人来改、项目不存在、或者 active tenant 对不上，都是 HTTP 404。不存在和无权看用同一个响应，避免靠状态码区分出别人有这个项目：

```json
{"code":114001,"message":"找不到这个项目","data":null}
```

**A3 挂接。** `POST /api/runs` 增加可选字段 `workspaceId`。预检失败是上面的 404，并且 `sessions` 和 `runs` 都不新增行。预检在会话准入之前。未登记的 `sessionId` 再加一个对不上的 `workspaceId`，回 `114001`。`workspaceId` 对得上、`sessionId` 却未登记，仍是 404 `{"code":112001,"message":"找不到这场会话","data":null}`。预检通过之后，新会话的 `workspace_id` 写成这个 id。worker 起 run 时读这一列：有值就 `MkdirAll` 到 `tenants/<tid>/workspaces/<wid>/`，没有值就仍用 `sessions/<sid>/`。2026-10-20 在 `127.0.0.1:8904` 打过：项目里的 `hello.md` 内容是 `abc`；同一项目的另一场会话 `read_file` 读到 `abc`；不带 `workspaceId` 的 `free.md` 落在会话目录；已有游离会话再带上合法 `workspaceId`，列仍是 NULL，新文件仍进会话目录。

**A5 挪动。** 新增 `PATCH /api/sessions/:id`，与现有的 `PATCH /api/sessions/:id/visibility` 并存。body 必须带 `workspaceId`。`{"workspaceId":"ws_x"}` 挂上。`{"workspaceId":""}` 解绑；去掉首尾空白后仍是空，也解绑。字段缺席，或 JSON 值是 `null`，是 HTTP 400 `{"code":111001,"message":"请求格式不对","data":null}`，不会当成解绑。挂上之前做和 A3 相同的项目预检。对不上是 HTTP 404 `{"code":114001,"message":"找不到这个项目","data":null}`，列不改。门槛是 `sessions.user_id` 等于当前用户。看不到这场会话的人，仍是 404 `{"code":112001,"message":"找不到这场会话","data":null}`。同租户里能看见、但不是本人的，是 HTTP 403 `{"code":111204,"message":"只有本人能修改","data":null}`。成功是新信封 HTTP 200。挂上时 `data.workspaceId` 是项目 id，解绑时是 `null`。已经写下的文件留在原地。下一场 run 的作业根读更新后的列，不搬旧文件。

2026-10-20 在 `127.0.0.1:8904` 打过。用户沿用 A3 的 `u_01M5AEXM1X5FCWHDM3M26TFVJW`，项目 `ws_01M5AEXM2D81379KN6HC2FKATN`，会话 `s_01M5AEXP8PT5XKX6VPX3E17SZT`。

```json
{"code":114002,"message":"项目里还有会话，先挪走再删","data":null}
```

等于 0 则删行，提交之后再 `RemoveAll` 项目目录。目录还没建过，`RemoveAll` 也算成功。别人的项目、已经删掉的项目，都是 HTTP 404 `{"code":114001,"message":"找不到这个项目","data":null}`。没带 token 是 HTTP 401 `{"code":111102,"message":"请先登录","data":null}`。

```json
{"code":0,"message":"","data":{"status":"deleted"}}
```

## 9. 存储与多副本

`Workspace` 经 GORM `AutoMigrate` 建表，不另写迁移文件。这和 `pgstore.go` 里现有表的建法相同。

列表会按 `tenant_id` 加 `user_id` 查，所以建表时带了复合索引 `workspaces_owner`。

归属和权限都在 PG 的行上。worker 起 run 时从 session 行读 `workspace_id`，再决定作业根。没有进程内缓存，也没有用 channel 等「当前项目」。多副本要读到同一批文件，仍然靠 `-workspace` 指向同一块共享盘。项目目录是 tenant 目录的子树。

## 10. 错误码

新码用 `114` 段。身份模块的 `111` 段不拿来表示项目不存在。

| code | 场景 | HTTP | 哪一拍开始用 |
|---|---|---|---|
| `114001` | 项目不存在，或当前用户不是创建者 | 404 | A2 |
| `114002` | 项目里还有会话，不能删 | 409 | A6 起用；2026-10-21 起退役，删除项目不再返回，码位不重用 |
| `114003` | 项目名称去掉空白后是空的 | 400 | A1 |
| `114004` | 项目正在另一场会话里运行 | 409 | A7d |
| `114005` | 默认工作区不能删除 | 409 | A8a |
| `114006` | 项目下有活 run，拒绝删除项目 | 409 | doc/37 D1 |
| `114007` | 会话下有活 run，拒绝删除会话 | 409 | doc/37 D3 |

`114003` 的 message 是「请填写项目名称」。tenant 名称是空的仍用 `111003`「请填写工作区名称」。两个空名称不是同一件事，页面靠 code 区分，弹窗文案用各自的 message。`114006` 的 message 是「项目里有正在运行的会话，等它跑完再删」。`114007` 的 message 是「这场会话正在运行，等它跑完再删」。`114002` 从 2026-10-21 起不再返回。

可见性不是 `private` 或 `tenant`，以及 body 里没有 `visibility` 字段，用已有的 `111002`，message 是「可见性只能是 private 或 tenant」，HTTP 400。缺 JSON 仍是 `111001`「请求格式不对」。不是创建者，或项目不存在，仍是 `114001`。

成功和失败都回 `code`、`message`、`data`。失败且没有额外内容时 `data` 是 `null`，字段仍在。HTTP 状态保持 400、401、404、409、500，不把失败收成 200。
