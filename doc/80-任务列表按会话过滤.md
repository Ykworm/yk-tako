## 1 病灶：一场会话派了什么，界面上根本不存在这个信息

一场真实使用：

```text
用户在会话 A 里让助手派发三件 Task（调研 / 汇总 / 出稿）
→ 开一场新会话 B，聊一件别的事
→ 右侧「任务」标签里躺着 A 的三件 Task（面板跟项目、不跟会话）
→ 他在 B 里又派了一件，新任务和 A 的三件混在同一张表里
→ 他分不清「我正在聊的这一场派了什么」——这个信息在界面上根本不存在
```

项目一多、会话一多就更糊：一个项目里几十场会话各自派过任务，列表成了一个没有主语的长表。

反过来也有需要全量的时刻——「我上周让助手跑的那批完成没有」。所以不是把列表绑死到会话，而是**默认看本会话、可一键看本项目**。

## 2 完整业务链路（谁 → 谁 → 谁）

```text
用户在场 S 的输入框发消息
→ 引擎跑一场 run（run 属于会话 S）
→ 助手调 delegate_task / create_orchestration
→ 建编排组 agent_orchestrations，列 source_session_id = S
→ 组内建 Task 行 agent_tasks（列 orchestration_id，本身没有会话列）
→ 调度器领件、跑执行 run、交结果
→ 右侧面板 / 任务页列这些 Task   ← 本方案动的是这一环的取数范围
```

本方案动的唯一一环：**列 Task 时按「谁派发的」（组的 `source_session_id`）缩小范围**。上游是建组时写下的与会话的关联；下游是列表渲染与详情抽屉。不改调度、不改执行、不改交付。

## 3 范围与非目标

范围：

1. 后端：`GET /api/workspaces/:id/tasks` 新增**可选**查询参数 `sessionId`（不加端点、不改响应字节）。
2. 前端：右侧「任务」标签（嵌入模式）与「任务」页都加两档切换（本会话 / 本项目全部），默认本会话。
3. 契约真源：`expected.json` 新增用例 80 + `doc/19v6-04-验收-curl.md` 同批加用例 80，散文与清单用例号集合一致。
4. 文档：本篇新增；doc/77 §3/§4.2、doc/78 §3/§4.5、doc/16 §2、doc/README.md §1 同批改口径。

非目标（明确不做）：

- 不改 Task 的存储、状态机、调度、交付与可见性链（`taskOwnerQuery` 一个字不动）。
- 不做会话选择器（不挑具体某一场会话，只区分「本会话 / 本项目全部」）。
- 不改「需要我处理」（`GET /api/workspaces/:id/task-attention`）的作用域，仍是项目级聚合（理由见 §4.5）。
- 不改「Todo」标签（`GET /api/runs/:id/tasks`，本来就是 run 级，不是本方案的「任务」）。
- 不做分页、不做服务端开关、不落偏好到 localStorage。

## 4 已拍定的设计选择

### 4.1 服务端过滤（可选参数），不是前端本地过滤

Task 的所属会话记在**编排组**上（`agent_orchestrations.source_session_id`），Task 行没有这一列，响应里也没有（`agentTaskView` 只有 `orchestrationId`）。前端要本地过滤就得逐条再拉一次 orchestration（N+1 请求）。加一个可选参数，是把「谁派发的」这个关系交给已经持有它的那一层。

没这么做会怎样：面板一打开就打几十个请求；或者把项目级关系搬到每一行任务上，将来再加一个维度就再加一列。

### 4.2 参数语义：纯过滤，不校验会话存在性

- `sessionId` 省略或空串 = 不限定（**字节与今天完全一致**）。
- 非空 = 只返回「所属编排组的 `source_session_id` 等于它」的 Task。
- 会话不存在 / 已删 / 不是本人的：**200 + 空列表**，不报 404。

理由：这是读面的**缩小范围参数**，不是资源路径。若校验存在性，就多一条会误报的失败面——会话在别的窗口被删掉后，面板会弹一条错误横幅，而用户看到的「本会话没有任务」本来是诚实的。而且按会话过滤不泄露任何东西：别人的会话在本人租户里根本查不到编排组，返回空列表与「本会话真的没有任务」同形，没有探测通道。

被否：像 `POST /api/tasks` 那样对未知 `sourceSessionId` 回 404 `112001`——那条是**写路径**的来源校验（建组要挂到一个真实会话上），语义不同，不能照搬。

### 4.3 两档切换，默认本会话

- 一个分段控件：`本会话` / `本项目全部`，放在列表头那一行（今天的「任务 N」+ 筛选框旁）。
- 默认：**能拿到当前会话 id 时默认「本会话」**；拿不到（新对话还没发过消息、或任务页没有活动会话）时默认「本项目全部」。
- 空态文案：搜索无结果 → 「没有匹配的任务。」；本项目无任务 → 「这个项目还没有任务。在对话里让助手用任务功能派发。」
  - 本会话档下本会话无任务时**不显示任何空态文案**（列表头已有「本项目全部」切换，不再重复提示）。2026-11-14 用户定。
- **不落 localStorage**：每次进页面都回到默认。理由：默认表达的是「我现在在看哪一场」，不是长期偏好；记住上次选择会让「新会话默认看本会话」这条当场失效。

### 4.4 两处入口同一份实现

右侧「任务」标签（`embedded` 模式）与「任务」页（整页）共用 `TasksView` 的同一个控件与同一份请求逻辑，不写第二套。

### 4.5 「需要我处理」仍是项目级（本方案明确不改）

面板顶部的处理条来自 `/api/workspaces/:id/task-attention`，今天就是项目级聚合，左侧导航那个入口吃的是同一份数据（doc/72 §8.2）。按会话过滤会让「别的会话里有事等我」从界面上消失——那恰恰是最不该丢的信号。所以处理条不动。

代价是面板里会出现「列表是本会话、处理条是本项目」的不一致。处理办法是**把限定词写出来**：`scope === 'session'` 时，处理块加一行标题「需要我处理 · 本项目」；`scope === 'project'` 时不加（不冗余）。两块各自的读法就是清楚的。

## 5 契约与施工面

### 5.1 后端（三个文件）

| 文件 | 改动 |
|---|---|
| `internal/runengine/server.go` | 路由不变（无新端点） |
| `internal/runengine/agent_task_api.go` | `listWorkspaceAgentTasks` 读 `c.Query("sessionId")`，透传给 store |
| `internal/runengine/agent_task_store.go` | `ListWorkspaceTasks(ctx, p, workspaceID, sessionID string)`：`sessionID != ""` 时追加子查询 |

SQL 形（在今天的 `Where("tenant_id = ? AND workspace_id = ?", …)` 之后追加）：

```go
if sessionID != "" {
    q = q.Where("orchestration_id IN (SELECT id FROM agent_orchestrations WHERE tenant_id = ? AND source_session_id = ?)",
        p.TenantID, sessionID)
}
```

- 索引已存在：`agent_orchestrations` 的 `(tenant_id, source_session_id, idempotency_key)` 唯一索引，子查询走它，**不新增索引**。
- `sessionId` 只作参数值走 GORM 占位符绑定，不拼字符串；子查询自带 `tenant_id = ?`，跨租户查不到。
- 响应字节一个字不变（同一个信封、同一份 18 键序的任务视图）：`TestContractAgentTaskViewBytes` 不动。

### 5.2 前端（四个文件）

| 文件 | 改动 |
|---|---|
| `web/src/api.ts` | `listWorkspaceTasks(workspaceId, sessionId?)`：`sessionId` 非空时拼 `?sessionId=`（`encodeURIComponent`），空串/省略时字节与今天一致 |
| `web/src/TasksView.vue` | 新 prop `activeSessionId?: string \| null`；列表头加两档切换（本地 `scope: 'session' \| 'project'`，默认见 §4.3）；`loadTasks()` 按 scope 决定传不传 sessionId；空态文案分两种；`watch(scope)` 与 `watch(props.activeSessionId)` 重拉列表；收到带 `taskId`/`orchestrationId` 的定位（`applyFocus`）或手动换项目时 scope 落「本项目全部」 |
| `web/src/ChatDock.vue` | 新 prop `sessionId`；转发 `:active-session-id` 给 TasksView；TasksView 的 `:key` 由 `workspaceId` 改成 `${workspaceId}:${sessionId ?? ''}`（换会话即重来，与换项目同一套语义）；`scope === 'session'` 时处理条加「需要我处理 · 本项目」标题 |
| `web/src/App.vue` | 给任务页 `TasksView` 与 ChatDock 挂载点都传 `:session-id="sessionId"`（`sessionId` 是 App 已有的 computed） |

任务页上的两条自动降档（`TasksView` 内部逻辑，不新增后端概念）：

- 用户在任务页手动换项目（项目选择器）→ 当前会话不属于那个项目，落「本项目全部」；
- 定位到某条处理项（左侧导航点进来，`focusTaskId`/`focusOrchestrationId` 非空）→ 落「本项目全部」，否则列表会把这个抽屉里的任务过滤掉。

### 5.3 必须保持的既有行为

- 不传 `sessionId` 时的响应字节与今天逐字相同（含排序：`created_at DESC, id DESC`）。
- 项目可见性不变：workspace 必须属于本人租户与本人，否则 404 `114001`。
- 任务可见性链不变（`taskOwnerQuery`：task → orchestration → source_session → 本人）。
- 详情抽屉、编排组视图、停止/恢复/发布、处理项、Todo 标签、事件重拉（`agent_tasks_changed`）、`reloadNonce` 重连重拉——全部不变。

### 5.4 没有临时实现，也没有过渡开关

- `sessionId` 空串 = 不传，是长期语义，不是兼容垫片；
- 不保留任何「按会话过滤」的本地开关或 env 变量；
- 不落 localStorage 偏好。

## 6 验收

### 6.1 机器（契约用例 80）

`expected.json` 用例 80（`id: 80-tasks-session-filter`、`tier: core`、`needs: pg`）：POST 建项目 → SQL 造两场来源会话（同项目同用户）→ 各派一件 Task → SQL 固定 `created_at` 钉住倒序 → 四条 `GET` 断言（不传 = 两件且顺序不变、`?sessionId=` 分别只剩本会话那件、`sessionId=s_nope` = 200 空列表）。期望字节**先 curl 实跑再抄**，不手写。同号散文进 `doc/19v6-04-验收-curl.md`；`check-expected.sh` 守两边用例号集合一致。

### 6.2 活体 curl（隔离引擎 8943）

```bash
B=http://127.0.0.1:8943; T=<access token>; W=<项目 id>; S=<会话 id>
curl -s "$B/api/workspaces/$W/tasks"              -H "Authorization: Bearer $T"   # 两件
curl -s "$B/api/workspaces/$W/tasks?sessionId=$S" -H "Authorization: Bearer $T"   # 只剩本会话
curl -s "$B/api/workspaces/$W/tasks?sessionId=s_nope" -H "Authorization: Bearer $T"  # 200 空列表
curl -s "$B/api/workspaces/$W/tasks?sessionId="   -H "Authorization: Bearer $T"   # 空串 = 不传（两件）
```

### 6.3 前端走查（浏览器，真引擎）

1. 开一场新会话（还没发过消息）→ 右侧「任务」标签默认「本会话」，空态文案是本会话那一条。
2. 在对话里让助手派一件 Task → 事件到达后它出现在列表里，不用手刷。
3. 切到「本项目全部」→ 看到本项目其他会话的任务；切回「本会话」→ 只剩这一件。
4. 点一条开详情抽屉 → Esc 关；编排组视图进出正常。
5. 切到另一场会话（同项目）→ 列表按新会话重来（不残留上一场的行）。
6. 切到另一项目的会话 → 面板只列该项目的任务（既有行为不变）。
7. 左侧导航点一条「待回答」处理项 → 任务页打开，档位自动落「本项目全部」，抽屉里是那条任务。
8. 任务页手动换项目 → 档位自动落「本项目全部」。
9. 刷新页面 → 档位回到默认（本会话），不记住上次。
10. ≤860px 视口无横向溢出、面板不渲染（既有行为不变）。

## 7 风险与边界

- **会话与项目不对齐**：任务页手动换项目、或定位到某条处理项时，档位自动落「本项目全部」——否则列表会把不在当前会话的任务过滤掉，看起来像「任务丢了」。这两处降档是规则不是临时补丁。
- **处理条与列表作用域不一致**：列表可能按会话收窄，而处理条是项目级。用「需要我处理 · 本项目」一行标题把限定词写出来，两块各自的读法就清楚；不引入第二种聚合。
- **按会话过滤不校验存在性**：这是有意的（§4.2），代价是「看不见的会话」与「本会话真的没任务」同形——但两者本来都不该有第二句话。

## 8 所以这解决了什么

用户在场 S 里派的任务，现在默认就在标着 S 的列表里；切到别的会话，列表整体换一场，不残留上一场的行；需要看全项目时一键切「本项目全部」。派发在对话里、执行在后台、结果回到对话，而「我在这一场派了什么」终于在界面上有了主语。
