# 租户运行时怎么装配

> 模块：run 装配（`internal/runengine/profile.go`、`worker.go`、`product_api.go`、`mcp.go`）｜ 状态：已落地（`doc/34` R1–R5 + U1，`9c21b66`，2026-10-19）｜ 证据：`doc/34-租户运行时装配.md`、`tmp/34-租户运行时装配/planning.md`

## 1. 场景与病灶

owner 建了一个团队 agent，填了 `model_ref` 和工具；member 选它发消息。prompt 换了，模型和工具仍是平台启动时那套——`newRunAgent` 写死 `Model: w.chat`、`Tools: w.tools`，`model_ref` / `tool_policy` 根本没被读。

更危险的是密钥：A、B 两个租户都用 `deepseek/deepseek-v4-flash`，各配自己的 key；旧的全局 `ModelRegistry` 只按 `ref` 缓存，第二个租户拿到的是第一个租户的 key。MCP 同理：租户在 config 里配了 server，run 仍只连平台 `mcp.json`，配了等于没配。

## 2. 候选与代价

| 问题 | 候选 | 好处 | 代价 |
|---|---|---|---|
| 团队 agent 是什么 | A 第二种 runtime | 概念独立 | 两套装配、两套故障面 |
| | B 这一场 run 的 root agent 配置来源（定案） | 一套 `ChatModelAgent`，只换输入 | 需要把配置收成不可变 profile |
| 子代理真源放哪 | A 继续扫 `agents/*.md` | 零迁移 | 多副本不共享文件系统；租户改不了、改了就影响所有租户 |
| | B DB 为准，md 只做 seed/导入（定案） | 多副本共享 PG；租户可覆盖 | 要 seed/导入两条通道与 `rescan` 式补偿 |
| 坏配置什么时候报 | A 先 202 再在 worker 里 error | 请求路径简单 | 用户看到「接受了却失败」，且已经占了一次并发闸 |
| | B 抢闸前 `validate(profile)`，坏配置直接 4xx、无 run 行（定案） | 失败立刻可见 | 建 MCP 连接要早于 `AcquireRun`，抢闸失败后必须关闭句柄 |
| 租户没配 key | A 回退平台 key | 开箱即用 | 等于租户之间隐形共享一把 key |
| | B 4xx，不建 run（定案） | 隔离成立 | 新租户必须先配 key 才能跑（111408，是设计不是故障） |
| 自定义 MCP 连不上 | A 降级少工具 | run 照跑 | 用户以为配好了，实际工具静默缺失 |
| | B 503、不建 run（定案） | 显式失败 | 与系统 MCP 的政策必须分开写：系统 MCP 失败才降级 |

**裁定：B / B / B / B / B。**

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 覆盖默认 agent 是增量还是全文？ | 全文 copy；默认更新不自动跟随，UI 显示「默认已更新」 | 增量合并会在两层都改同一字段时产生第三种语义 |
| `tool_policy` 几种模式？ | `inherit` / `allow` / `exclude` / `none` 四态；`names` 只在中间两态合法 | 与子代理四态同形，避免第二套词表 |
| 子代理能借配置扩权吗？ | 不能：子代理工具池必须是根有效池的子集 | 否则 md/UI 就是提权入口 |
| 模型缓存键？ | `tenantID + ref + configVersion`，每进程一份 | 配置改后必须换键，否则旧 key 的 client 被复用 |
| 哪些调用走租户 resolver？ | root、子代理、记忆抽取、压缩摘要全部 | 缺一条就有后台任务偷偷用平台 key |
| 系统 MCP 失败怎么办？ | 降级为少工具，UI 黄色 degraded | 平台自己配的东西挂了不该拖垮租户 run |
| 409 抢闸失败后刚建的 MCP 连接？ | 立刻 `RunProfile.Close()` | 否则进程里留句柄，多副本下泄漏 |
