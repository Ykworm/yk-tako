# 子代理窗口谁来压

> 模块：子代理 / 上下文压缩（`internal/runengine/`）｜ 状态：已落地（`ceecc28`，2026-10-17）｜ 证据：`doc/25-子代理折叠.md`、`tmp/17-子代理折叠/planning.md`、commit `ceecc28` / `496d54d`

## 1. 场景与病灶

用户让 researcher 连着搜读四五份长材料，它在自己的 ReAct 循环里一轮轮调工具，主线程只等终稿。

子代理是独立实例、独立窗口。主 run 的折叠链挂在主 run 的 handler 上，管不到子代理进程内的消息列表。于是子代理的窗口先满：下一次模型调用被 provider 以「上下文超长」拒收，委派错误原样上抛，**整场 run 变成 error**。用户看到的是「失败」，不是报告。

旧结论（19v6-10）写的是「子代理内部不压」，理由是「跑完即弃、回传有上限、摘要没有下一个读者」。这个理由在单轮短任务下成立；在「多轮长材料」这个真实场景里，**下一个读者出现了——就是子代理自己的下一次模型调用**。

## 2. 候选与代价

| 候选 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 不压 | 沿用 19v6-10 | 零改动，子代理跑完即弃 | 多轮任务必死于窗口溢出 |
| B 进程内折叠 | 在子代理装配点挂 `agentFoldHandler`，只重写 `state.Messages` | 交终稿前自行压短，父 run 保持 complete；主线程形状不变 | 要复刻主链的「估/折/滤」；摘要套摘要；必须无状态 |
| C 落进主 run 的 mh 再压 | 复用主 run 的落库链 | 坐标不丢、可审计 | 污染主 run 投影；子代理摘要会被 UPSERT 成主 run 的 `seq=0`，主线程形状被改写（doc 明令不做） |

**裁定：B。** 只压子代理进程内那份列表，不往 `run_model_messages` 插行、不占主 run 的坐标。

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 用主 run 同一条链还是给子代理单开窗口？ | 复用主 run 同一条链：同一 counter、同一把 `compactLimit`、同一摘要器、同一份 fileEffects | 子代理窗口不能独立调；压测窗必须高于 root 全场用量。好处是零新旗标、行为不分叉 |
| 折叠产物落库吗？ | 不落，明确接受「摘要套摘要」 | 主线程形状不变、runlog 工具行不动；代价是下一次折叠把上次摘要当普通历史再摘一遍，只影响终稿措辞密度 |
| handler 能持有每委派状态吗？ | 不能：base 行、上一轮计数、上一次摘要都不许存字段 | eino ToolsNode 默认并行，同名委派共享同一个 handler 实例；字段必串。每次委派唯一属于自己的东西是 ADK 传进来的 `state` |
| 折叠失败或 provider 溢出，杀整场 run 还是降级？ | 都转成错误文本当委派结果 | 父 run 保持 complete，主线程还能继续；手动停止的 ctx 取消仍裸上抛（那是真的要停，转文本会骗模型继续干活） |
| 滤思考和 Usage 触发跟折叠同一拍吗？ | 同一拍，三步一起做（估 → 折 → 滤），验收分主次 | 只做折叠会留下「每枪重发思考 + 每轮全量 BPE 重数」两个已知病灶；A1 diff 超 80 行目标被明确接受 |
| 子代理中间态要不要为崩溃恢复落盘？ | 本拍不落；后来由 doc/39 只落「完整跑完」的档案供 resume | 分界线不是「文件 vs 数据库」，是「谁裁决多副本并发」 |
