# 笔记按什么分区

> 模块：记忆 / 笔记（`internal/runengine/notes.go`）｜ 状态：已落地｜ 证据：`doc/17-后续计划-代码子代理与记忆.md` §7、`tmp/17-笔记/planning.md`

## 1. 场景与病灶

笔记（`notes` 表）是模型用 `memory` 工具显式写下的长期事实：用户说「不要重建」，模型记一笔；查清了部署路径，模型记一笔。下一场会话起手时，这些笔记排进系统提示，模型不用再问一遍。

「按什么分区」决定这个功能有没有意义：

- **按会话分**：新会话读不到旧笔记。而笔记最核心的用例就是「跨会话记住上一场查到的路径」——按会话分等于没有记忆。
- **按用户分**：今天没有独立的用户表（身份挂在租户与 membership 上），要新造一层。
- **按 workspace 绝对路径分**：物理工作区就是边界；同一项目的多场会话共享一份笔记；跨项目天然隔离。代价是同一 workspace 的多个人共享一份。

围绕这个分区，还有一串必须一起定的细节：字数上限的原子性、快照什么时候读、改口时旧原话留不留、注入检查拦什么、写失败怎么收场。

## 2. 候选与代价

| 问题 | 候选 | 好处 | 代价 |
|---|---|---|---|
| 分区键 | A 按 session | 隔离强 | 跨会话不可见，等于没记忆 |
| | B 按 workspace 绝对路径（定案） | 物理工作区即边界，零新表 | 同 workspace 多用户共享一份 |
| | C 加 `user_id` | 语义最准 | 现在没有用户表，要先造身份层 |
| 字数上限检查放哪 | A 进程内 mutex | 便宜 | 多副本失效，等于没锁 |
| | B 先算合计再插入、不锁 | 简单 | 两个会话各自看见「没超」，合计超上限 |
| | C 同一 PG 事务里 advisory xact lock → 算合计 → 插入（定案） | 跨进程正确 | 每写一次加锁，吞吐下降 |
| 快照何时读 | A 每次模型调用重读 | 即时 | 场内系统提示会变，折叠长度基线漂移；模型看见自己刚写的笔记，自我强化 |
| | B 每场 run 起手读一次、run 内冻结（定案） | 稳定、可解释 | 本场新写的笔记本场不可见 |
| 改口怎么留痕 | A 原地 UPDATE content | 表小 | 历史不可对质，旧原话被覆盖 |
| | B 新插一行、旧行只填 `superseded_by`（定案） | 旧原话、quote、runlog 位置完整保留 | 行数增长，所有读侧要过滤未替代 |
| 注入检查拦什么 | A 句式词表 | 能表达「不许做什么」 | 拦不住语义；纯中文写法一条不命中，清单列不尽 |
| | B 只拦隐形字符（17 码点）（定案） | 有限、可枚举尽、与语言无关，拦的是「能不能藏」 | 挡不住明文字面注入 |
| 写失败出口 | A Go error 上抛 | 失败显眼 | 一次记笔记失败把整场 run 打成 error |
| | B 工具结果错误文本 + 连续 3 次后劝停（定案） | 模型可改参数重试，run 照常 | 模型可能反复试，需要劝停 |

**裁定：B / C / B / B / B / B。**

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 折叠时用户规矩留原句吗？ | 折叠提示词加一句「用户明确说过的规矩按原句留在摘要里」 | 摘要略变长，但明确规矩不会随机丢失 |
| 从摘要自动往笔记表插行吗？ | 不插 | 自动生成的是模型二手概括，不是用户原话，会污染「显式记忆」契约 |
| 子代理继承主线程模型历史吗？ | 不继承，只给任务说明与工具池 | 40 份日志与搜索原文留在子代理，隔离才成立 |
| 团队笔记谁写？ | `scope=tenant` 行 `user_id` 记创建者，全租户可读，仅 owner/admin 可写，模型默认不能写 | 模型一次误写不会污染全团队；快照要合并 user + tenant 两份 |
| 存量毒行怎么办？ | 渲染时换占位文字 | 不删除历史，但下一场不会被注入 |
