# 没有沙箱的系统怎么办

> 模块：bash 沙箱（`internal/runengine/sandbox.go`、`bash.go`、`mcp.go`）｜ 状态：已落地（2026-11-03；Debian 活体待跑）｜ 证据：`scripts/acceptance/linux_sandbox.sh`、`tmp/35-linux-bash沙箱/planning.md`、`doc/28-多租户.md` §（Linux 口径）、`doc/52` D16/D37

## 1. 场景与病灶

试用要卖的是「能动手的 agent」：客户传一份 PDF 问「主要讲什么」，agent 要能 `pdftotext`、写脚本、跑 python 抽正文。dev 机器是 macOS，`sandbox-exec` 把 bash 关进会话目录；试用机是 Debian，没有 `sandbox-exec`。

于是 Linux 上每一次 bash 都回一句「这台机器的 sandbox-exec 不能 apply，不能把工作目录当成隔离」，模型只能说「我执行不了命令」，只好按文件名猜内容。十来个客户每人试两下，试用结论就是「这产品一半功能是坏的」——而且每失败一次还烧一轮模型往返。

## 2. 候选与代价

| 候选 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 放开裸 bash | `requireSandbox=false` 直接跑 | PDF 场景当天可用 | 工作区在 `tmp/workspace/tenants/<tid>/…`，引擎 `.env` 就在上一级：`cat ../.env` 就能拿 key 再发出去，还能读别的租户、`rm -rf` 全工作区。`bashEnvWhitelist` 只挡环境变量，挡不住磁盘文件 |
| B bubblewrap 后端 | Linux 上加 bwrap：挂载表 + 命名空间，与 macOS 语义对齐 | 真隔离；Debian 官方源有；codex 也内置 bwrap | 要维护两套后端；`npx` 式依赖下载路径会撞围栏（MCP 同理） |
| C Landlock | 用内核 Landlock 做文件隔离 | 不依赖安装 bwrap | Debian 12 内核 6.1 只有 ABI v2，只管文件；作为 bwrap 不可用时的后置方案 |
| D 容器 | 每个 bash 进容器 | 隔离最强 | 首拍背镜像、卷、网络、启动延迟 |

**裁定：B；A 不做；C 后置；D 不做。**

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| probe 怎么做？ | 不只 `LookPath`：真跑一次最小沙箱，stdout 含探针串才算 ok | 区分「binary 不在 / userns 被禁 / seccomp 挡住」三种失败 |
| probe 不过怎么办？ | 继续拒绝（fail closed），错误文案改成可行动的一句话（提到装 bubblewrap） | 不提供「裸 bash」开关、不把 bwrap 设 setuid |
| bwrap 挂载表？ | **逐个卸命名空间**（user/pid/ipc/uts/cgroup，**不卸 net**）、`--die-with-parent`、`--new-session`、`--proc /proc`、`--dev /dev`、`--tmpfs /tmp`；`/usr` 只读、`/etc` 只白名单文件；**只 bind 会话根可写** | 绝不 `--ro-bind / /`——那会把 `.env`、home、别的租户全部只读暴露；不 bind `$HOME`。不用 `--unshare-all`：它含 net，会把 D37 的出站网络一起断掉 |
| 会话根之外能看见什么？ | 系统目录只读；看不到引擎目录、其他租户目录、用户 home | 父目录不 bind，兄弟租户天然不可见 |
| 后端怎么可见？ | 启动日志一行 `bash sandbox: seatbelt / bwrap / none（bash 工具将拒绝执行）`；dev 端点 `sandboxed` 与实际后端一致 | 配错在启动日志里就暴露，不等客户第一次调工具 |
| 超时/杀进程语义变吗？ | 不变：外层 `exec.CommandContext` 杀 bwrap，`--die-with-parent` 带走沙箱 | 与现有 bash 收尾惯例一致 |
| 沙箱内有网吗？ | **2026-10-28 翻案：出站开、入站不开**（`doc/52` D37）；bwrap 因此不卸 net namespace | 技能正文里的 `curl`、下载数据集、调外部 API 是常见步骤；断网等于把技能判死。代价：bwrap 进程能在宿主网卡上 bind 端口（macOS 侧是「入站禁」），这是两套后端唯一的已知语义差 |
| 技能脚本的权限？ | 继承围栏：项目根可读写、系统路径只读、出站开 | 准确含义是「第三方代码能以改整个项目、能出网的权限跑，但写不到围栏外」 |
| Linux 上 MCP 呢？ | 与 bash 同口径：走同一个后端（bwrap），根 = 该租户目录；probe 失败 → 拒绝启动租户 MCP | 不假装已隔离 |

## 4. 证据

- 方案：`tmp/35-linux-bash沙箱/planning.md` §0–§4（背景、病灶、候选、bwrap 命令形状、probe）；`doc/28-多租户.md` §9.4（Linux 口径）；`doc/33` 头注（租户 MCP fail closed）；`doc/52` D16（Linux 沙箱单独 loop）、D37（出站网络）。
- 代码（现状，2026-11-03）：
  - `sandbox.go` 后端选择 `currentSandboxBackend()`／`detectSandboxBackend()`：先真跑 seatbelt 探针，再真跑 bwrap 探针；全失败回到 `none` 并把原因带进启动日志与拒绝文案。
  - `bwrapArgs()` 生成挂载表；`startBash()` 的 bwrap 分支与 `sandboxWrap()`（租户 MCP）共用它，`--` 后面接原命令。
  - `bash.go` 产品路径恒 `requireSandbox=true`；`mcp.go` 在 `sandboxWrap` 返回错误时拒绝启动。
  - 启动日志：`main.go` 打 `bash sandbox: <seatbelt|bwrap|none（原因…）>`；dev 端点 `sandboxed` 取自同一份后端探测。
- 单测：`linux_sandbox_test.go` 钉 bwrap 挂载表金样（绝不 `--ro-bind / /`、绝不 `--unshare-net`）与探针失败路径；`bashfence_test.go`／`skillfence_test.go` 的拒绝判据兼容两套后端的报错文案。
- 活体验收：`scripts/acceptance/linux_sandbox.sh`（Debian 上跑：能干活、越界读、越界写、出站网络、超时与孤儿进程）。

## 5. 现状

**已落地（2026-11-03）**：macOS 仍走 seatbelt（改动前后 dev bash 端点输出逐字节相同，启动日志 `bash sandbox: seatbelt`）；Linux 走 bwrap，挂载表见 §3；两套后端共用「probe 不过就拒绝」的 fail closed 口径，不提供裸 bash 开关。

**还没做的一步**：Debian 12 上的活体没跑过——本轮开发机是 macOS，没有 bwrap/Docker。代码已通过 `GOOS=linux GOARCH=amd64 go build` 与 linux 目标的 `go vet`，但这只证明能编译，不证明隔离成立。上线前在试用机跑 `scripts/acceptance/linux_sandbox.sh`（给 `TAKO_BASE` 与 `TAKO_ENGINE_LOG`），五条全绿才算 A2 收口。
