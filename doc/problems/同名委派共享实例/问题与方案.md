# 同名委派共享实例

> 模块：子代理（`internal/runengine/agents.go`）｜ 状态：委派路径已翻案落地（`496d54d`，2026-10-23）；主 run 实例仍共用（未决）｜ 证据：`doc/25-子代理折叠.md` §6–§7、`doc/28-多租户.md` §10.3、`tmp/17-子代理折叠/planning.md` §3

## 1. 场景与病灶

模型在一条 assistant 消息里同时发两个同名 `researcher` 委派。eino 的 ToolsNode 默认并行执行，两个 goroutine 进入同一个 `ChatModelAgent` 实例。

上游 eino issue #1177 的问题是：`msgConf.cancelCtx` 是**实例级可写字段**。当前接线没有启用 `adk.WithCancel`，所以绝大多数时候写的是 nil，带 `-race` 跑也不报功能错误——这是一个**潜伏的串线**：一旦将来启用 WithCancel，一个委派的 stop 会取消另一个委派；多租户下更严重，从「同一个人开两个标签页」升级成「两个租户互相污染」。

同一个根因还有第二层：如果子代理的 handler 或装配里存了任何 per-delegation 状态（base 行、上一轮计数、上一份摘要），同名并行就会互相串。

## 2. 候选与代价

| 候选 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A per-name 互斥 | 同名委派串行，异名仍并行 | 不动上游，能治委派路径 | 同名串行；主 run 的实例没有名字可分，治不到 |
| B 强制重建绷带 | 每次委派都重建实例绕开共享 | 绕开共享 | 贵、非治根；`returnDirectly` 为空也不构成重建理由 |
| C per-delegation 全量重装 | 装载时点整体挪到每次委派 | 彻底无共享 | 丢掉 run 级观测面与拒载时机；2026-10-16 判「不做」 |
| D 壳化 | 装载输入与观测面维持 run 级，只有 eino 实例推迟到每次委派、新建即弃 | 既无共享，又保住 run 级观测与预检 | 多一层壳；实例创建成本摊到每次委派 |

**裁定：先采纳 A，B 不做，C 于 2026-10-23 翻案为 D。** 「per-delegation 重装不做」这个中间态已作废——翻案的是「装载时点全挪走」，不是「实例必须共享」。

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 子代理 handler 可以有状态吗？ | 不可以，全部走参数与 `state` | 同名并行共享实例，字段必串；这是无状态写法的直接原因 |
| 主 run 的实例共享怎么办？ | 仍共用；doc/28 §10.3 明示「启用 `adk.WithCancel` 前必须按四条决策处理」 | 目前无 WithCancel，风险潜伏；这是全库唯一「裁定不完整」的条目 |
| 壳化之后还要 per-name 互斥吗？ | 原 #1177 动机被壳化吸收；是否另有动机未重拍 | 现状：异名并行、同名各自新实例，互不共享 |
