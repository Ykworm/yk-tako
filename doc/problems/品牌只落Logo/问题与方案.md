# 品牌只落 Logo：换图标，不动产品配色

> 模块：前端 · 品牌资产接入（tmp/tako-brand-integration）｜状态：**方案已定、未施工**（2026-10-31 核实：`web/public/` 不存在，`index.html` 无 icon 链接，`App.vue` 仍是旧 `t`）｜证据：`tmp/tako-brand-integration/{planning,todos}.md`、`tmp/tako-brand/final/`、`yk-tako-eino/web/{index.html,src/App.vue}`

## 1. 场景与病灶

品牌已经定稿——「Tako Grid」图形 + 06 燕麦焦糖双色 + 轮廓化字标。素材在 `tmp/tako-brand/final/`（`tako-mark.svg`、`tako-logo-horizontal.svg`、`AppIcon.appiconset/` 等）。

但运行 `./scripts/dev.sh` 打开页面，看到的还是旧的**黑底白字字母 `t`**；浏览器标签没有 favicon；Safari「添加到主屏幕」也没有方形图标。

原因不是设计没做，而是**两处断链**：

1. **素材在 `tmp/`**——`tmp/` 被 `.gitignore` 排除、验收后会被清理，它不是资产存放处。换个 clone 或清一次台账，定稿素材就没了；这与「验收脚本必须从 `tmp/` 搬进 `scripts/acceptance/`」是同一个病。
2. **页面没有引用**——`web/public/` 目录不存在，`index.html` 里没有 `<link rel="icon">` / `apple-touch-icon`，`App.vue` 的侧栏与登录页仍是 `.mark` 的字母 `t`（`App.vue:1272`、`:1468`）。素材再漂亮，没有一条稳定的 HTTP 路径到达它，等于不存在。

后果很具体：演示时第一眼是旧品牌，截图与文档对不上；若此时有人清 `tmp/`，定稿 SVG 与 PNG 源文件一起消失，只能重做。

## 2. 候选与代价

| 候选 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 继续用字母 `t` + CSS | 现状 | 零改动 | 品牌与产品不一致；定稿素材闲置；主屏幕图标缺失 |
| B 内联进组件（base64 / 大段 `<svg>`） | 把 Logo 塞进 `App.vue` | 少一个静态文件 | 每次渲染重复携带；favicon / apple-touch-icon 仍需要独立文件；改图要改组件 |
| C 静态资产进 `web/public/brand/` + 三处引用（选定） | 复制三份定稿资产；`index.html` 接 favicon 与 apple-touch-icon；侧栏与登录页换成同一横向 Logo | 一条稳定路径（`/brand/...`）；页面与标签/主屏幕同源；回滚只需删目录 + 还原两个文件 | 多三份二进制/矢量资产；两处品牌要同时换，漏一处会出现两套 |
| D 顺便把整套 UI 换成燕麦焦糖主题 | 改 token / 全局配色 | 「统一」 | 产品配色是另一条已验收的设计线（doc/51 中性现代风）；品牌替换借机改主题会把两件事的验收混在一起 |
| E 建原生 iOS 工程 + 完整 AppIcon | 拷 `AppIcon.appiconset` 进 iOS target | 原生图标完整 | 仓库今天没有 iOS target；为一个不存在的宿主建工程是空转 |

选 C。边界写死：**只换品牌呈现，不改产品配色 token、不改任何 API/存储/运行协议。** 完整 `AppIcon.appiconset` 留在素材 ZIP 里，将来真有 iOS target 再拷。

## 3. 接线的四个落点

| 落点 | 做法 | 为什么 |
|---|---|---|
| `web/public/brand/tako-mark.svg` | 独立图形，作 favicon | Vite 从 `/brand/...` 直接提供静态文件，无需打包 |
| `web/public/brand/tako-logo-horizontal.svg` | 横向 Logo，**字标已轮廓化** | 不依赖访问者本机是否装 Menlo；否则换台电脑字标就变字体 |
| `web/public/brand/tako-apple-touch-icon.png` | 180×180 方形图标（源 `icon-iphone-60@3x.png`） | iOS「添加到主屏幕」要 PNG，不吃 SVG |
| `web/index.html` | 加 SVG favicon + apple-touch-icon 两个 `<link>`，保留 `theme-color` 与标题 | 标签页与主屏幕先于页面内容可见 |
| `App.vue` 登录后侧栏 `.brand` | 用横向 Logo 替换字母 `t`；保留「工作区」副标或等价可访问名称 | 主工作台入口的品牌 |
| `App.vue` 未登录 `.gate-copy` | 同一张横向 Logo；保留 `h1` 语义或等价可访问标题 | 冷启动第一眼；两处必须同一套 |

窄屏约束：860px 以下顶栏不允许横向溢出，品牌副标按现有窄屏规则隐藏（`App.vue:3213-3214`）；390px 下登录页 Logo 不挤压右侧登录卡片、不出现横向滚动。

回滚：删 `web/public/brand/`，还原 `index.html` 与 `App.vue` 的本拍小块改动即可，不触碰其他文件。

## 4. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 资产放哪 | **`web/public/brand/`**，不放 `tmp/`、不内联 | `tmp/` 不入库且会被清理；内联解决不了 favicon / 主屏幕图标 |
| 改名后的 PNG 叫什么 | `tako-apple-touch-icon.png` | 语义化命名，避免把 `icon-iphone-60@3x` 这种源文件名带进代码面 |
| 字标用字体还是轮廓 | **轮廓化 SVG** | 不依赖访问者本机字体；跨平台一致 |
| 换不换产品配色 | **不换** | doc/51 已定中性现代风；品牌是图形与字标，不是主题 |
| 登录页与侧栏 | **同一套横向 Logo** | 两处不同会出现「两个品牌」 |
| 旧 `.mark` 样式 | **本拍清掉**，不留两套 | 否则下次改品牌会漏改一处 |
| 是否建 iOS 工程 | **不建** | 没有 target；完整 AppIcon 留在素材 ZIP |
| 可访问性 | 保留 `h1` 或等价标题、图形 `aria-hidden` | 图形不是文字，读屏要读得到「tako」 |
| 验收方式 | 先 curl 静态字节，再看浏览器两处 + 窄屏 | 资产先能被 HTTP 打到，页面才谈得上引用 |
| 要不要改 `doc/` | **不改**（当时判断） | 这是视觉资产接入，不是产品能力增减；本次补录进问题库以保住决策 |

## 6. 现状

- **方案仍有效**：静态资产进 `web/public/brand/`、三处引用、字标轮廓化、不换主题、不建 iOS 工程、回滚只碰三个文件。
