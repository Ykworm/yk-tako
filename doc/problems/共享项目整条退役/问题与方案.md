# 共享项目整条退役

> 模块：产品形态 / 项目目录（`internal/runengine/product_api.go`）｜ 状态：已翻身裁（`44cf7ca`，2026-10-22）｜ 证据：`doc/42-产品形态收窄与共享项目退役.md`、`doc/35-项目目录.md`

## 1. 场景与病灶

团队用户期待「像 Figma 一样一起改同一个项目」：A 在项目里开一场会话说「把结论写进 report.md」，B 同时开另一场说「把 report.md 的第二节改一下」。

如果项目允许共享，两场 run 在同一目录里并发写同一块可变状态：

- 一个 agent 读另一个 agent 写到一半的字节；
- `bash` 一句话清掉对方十分钟的产物；
- 两边都向用户报「成功」。

而「共享文件」真正要做的是**协同编辑**：CRDT / OT、在线状态、冲突合并、版本历史、撤销重做。tako 没有这个地基；做一个「能看见但不能同时改」的共享，只是半成品。

## 2. 候选与代价

| 候选 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 保留 `private` / `tenant` 双值，做共享项目 | 团队叙事完整 | 要权限矩阵 + 并发闸 + 附件可见性传导，且仍不是协同编辑 | 等于做另一个产品 |
| B 项目只写 `private`，共享退役 | 归属简单、无跨成员并发 | 对外故事少一条 | 团队只共享账号、额度、审计，不共享项目 |

**裁定：B。** 项目属于个人；团队共享的是账号、额度与审计，不是文件树。

这次收窄连带退役三样东西：

1. `?scope=tenant` 与 workspace visibility 端点 → 恒 404（`114001` 退役说明）。
2. 项目闸（同项目同时只允许一个活 run）→ 退役，改为「允许并发 + 文件指纹显式失败」。
3. 「乐观并发远期缝」→ 撤销。

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 并发写怎么防？ | 允许并发，flock + 内容指纹，冲突显式失败 | 详见 `doc/problems/同项目并发写文件怎么防`；跨机靠指纹「事后发现」，不能事前串行 |
| 索引 `one_live_run_per_workspace` 先删还是先发代码？ | **先发新代码（保留 409 兜底），再删索引** | 先删索引会让旧代码把冲突翻译成 500/未知错误，出现坏行为窗口；先发码则窗口内用户看到的仍是 409，行为不变 |
| 表上的 `visibility` 列删不删？ | 保留但只写 `private` | 删列要 DDL；保留列 + 端点 404 已足够，避免迁移风险 |
| 前端项目页还显示成员共享吗？ | 不显示；邀请流、成员页与项目页彻底分开 | 否则用户会以为还能共享 |
