# 会话默认私有

> 模块：多租户可见性 / 会话 API（`internal/runengine/session_access.go`）｜ 状态：已落地｜ 证据：`doc/28-多租户.md` §7.1、`doc/37-删除与档案清理.md` D-f、`tmp/28-多租户/planning.md`

## 1. 场景与病灶

团队租户里，Bob 和 Alice 在同一个 workspace 下工作。Bob 想看看 Alice 的会话列表和对话正文——毕竟「我们是一个团队」。

两种默认都会出事：

- **默认租户内可见**：新成员一进团队就看到全员的聊天记录与文件；有人把私人对话、客户材料、密钥片段留在会话里，全部裸奔。
- **一刀切 404**：把「同租户可读」的合理协作诉求也堵死，团队功能名存实亡。

还有一条更隐蔽的：**可见性传导**。如果「会话可读」自动让「会话里的附件、帧流、历史」都可读，那么私有会话分享出去时，附件也跟着泄露；如果分享只读，但写/停止不校验，成员能改别人的对话。

## 2. 候选与代价

| 候选 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 默认 tenant 可见 | 同租户成员都能读 | 协作零操作 | 隐私裸奔；没有「私人会话」这个选项 |
| B 默认 private，owner 显式改 tenant；tenant-visible 只读 | 默认安全，协作可开 | 分享多一步操作 | 要维护 owner/read 两种访问语义；前端要有可见性开关 |

**裁定：B。** 四条配套规则：

1. 默认 `private`；owner 显式改成 `tenant` 后才对同租户可见。
2. **可见即可读，写/停仍 owner**：tenant-visible 的会话，别人能看帧与历史，不能发消息、不能 stop、不能删。
3. **无权访问的 frames 回 200 + `gone`**，不回 403——不泄露「这个 id 存在」。
4. 附件跟着容器（workspace）走，不跟着会话可见性传导。

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 谁能删会话？ | **仅属主本人**；tenant owner/admin 不豁免 | doc/28 原表写的「owner/admin 可代删」与「会话默认私有」自相矛盾，doc/37 D-f 作废旧口径。代价是离职清理要本人操作 |
| 看不见的会话回 404 还是 403？ | 404 | 403 等于确认「这个 id 存在」；软删会话同样视同不存在 |
| 可见性字段存在哪？ | `sessions.visibility`（private/tenant） | 读侧统一走 `SessionAccess`；前端开关调 `PATCH /api/sessions/:id/visibility` |
| 分享后历史帧、运行中帧都能看吗？ | 能看，但写操作仍校验 owner | 读与写用两个不同判据，不能用一个 `owner` 位糊过去 |
