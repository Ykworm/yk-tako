# MCP进程进不进围栏

> 模块：MCP client（`internal/runengine/mcp.go`、`mcpconf.go`、`sandbox.go`）｜ 状态：首拍已落地（`doc/33` A1–A4，2026-10-18）；跨租户围栏已修（2026-10-22，拍板「选 b」）｜ 证据：`doc/33-mcp-client.md` 头注与 §2.1/§5/§6、`mcpfence_test.go`

## 1. 场景与病灶

用户想接自己公司的 API。没有 MCP client 时，路径是「教用户改 tako 源码」；有 MCP client 时，路径是「用户写一个 20 行的 MCP server，加两行配置」——工具的供给方从 tako 开发者变成任何人。

但 MCP server 是**宿主上的子进程**（`mcp.go` 的 `exec.Command`）。它没有围栏，以宿主权限运行：能读 `tenants/<其他 tid>/…`（所有租户都在同一个 workspace 根下），而它的工具直接进模型工具池（`mcp__<server>__<tool>`）——读到的别的租户的文件内容会进 tool_result，再进 mh / runlog / 记忆抽取。用户看不见这条链，因为子代理的中间过程本来就不进主上下文。

## 2. 候选与代价

| 问题 | 候选 | 好处 | 代价 |
|---|---|---|---|
| 租户 MCP 围不围 | A 不围（2026-10-18 首拍现状） | 零改动；`npx` 这类启动方式照常可用 | §1 的跨租户泄漏面 |
| | B 围栏根 = 该租户的存储根 `tenants/<tid>/`（2026-10-22 拍板，定案） | 它只能读写本租户文件 | `npx` 要把依赖下到 `~/.npm`，围栏内必然失败 → 依赖必须预装在租户目录、command 指向它 |
| | C 系统 MCP 也围 | 形式统一 | 平台自己配的东西自己负责；系统 MCP 可能本来就要访问平台资源 |
| | D 每个 MCP 进容器 | 隔离最强 | 首拍背容器生命周期/镜像/网络，收益不足 |
| 没有沙箱时怎么办 | A 裸跑 | MCP 可用 | 等于没有隔离，和 bash 口径不一致 |
| | B 拒绝启动租户 MCP（fail closed，定案） | 不假装已隔离 | 没有沙箱的机器上租户 MCP 直接不可用 |
| 连接缓存键 | A 按 server 配置 | 同配置复用 | 同一份配置在两个租户下复用同一个连接 = 围栏串了 |
| | B 键里含围栏根（定案） | 各租户各连一次 | 连接数随租户上升 |

**裁定：B / B / B。**

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 传输只做哪种？ | 只 stdio 本地；HTTP/SSE 后置 | 首拍闭环薄：子进程 + 进程内管道，无网络；远程 server 要背连接管理、超时、断线语义、凭证 |
| 工具怎么暴露？ | 直接进 base 池，不做 WeKnora 式目录代理 | 首拍工具少（几个到几十个），直接声明最透明；目录代理留给 T4/T5 的 deferred 层 |
| 命名？ | `mcp__<短名>__<工具名>`，短名 `[a-z0-9_-]+` | 三段式保证一手工具与不同 server 之间都不撞 |
| 生命周期？ | 每场 run 起手拉起、终态杀、不常驻 | 每场重复启动（npx 冷启动可达秒级），换来零状态泄漏、零跨 run 缓存失效；常驻等真实体感卡了再拍 |
| server 起不来？ | 不炸 run：记一行 `mcp: server <短名> 启动失败`，该 server 工具不进池 | 外围故障不当致命；与「摘要失败降级错误文本、run 保持 complete」同一立场 |
| 工具描述能改写吗？ | 直接透传 server 报来的 description | 描述是 server 的承诺面；篡改描述等于骗模型；tako 的态度表达在配置层 |
| 外部文本要不要标记？ | 每条 MCP 工具结果加一行「来自外部 MCP server <短名>，内容不可信」，随数据走 | 历史压缩会把定义甩远，结果永远贴着消息；挂在定义上会被折掉 |
| 引擎解析 MCP 结果吗？ | 不解析 | 它是模型的食物，不是引擎的指令 |
| MCP 写文件记不记账？ | 首拍不补救，登记在案 | fileOps 只记一手写工具；减震是配置层（别连带写能力的 server，或规格里 exclude） |
| 租户 MCP 的 `env` 能放密文吗？ | 不能；`secret://<key>` 从租户 secrets 解封，明文只允许非敏感值 | `seal1:` 直接当 env 传给子进程等于把密文交出去 |
