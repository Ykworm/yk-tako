# 项目目录归谁

> 模块：产品面 / 项目目录（`internal/runengine/product_store.go` / `media.go`）｜ 状态：已落地｜ 证据：`doc/35-项目目录.md`、`tmp/35-项目目录/planning.md`

## 1. 场景与病灶

用户为「Q4 调研」连开三场会话：第一场搜集资料写了 `中间产物.md`，第二场想接着读；第三场贴了一张图给模型看。

如果每场会话各有一个私有子目录：

- 第二场 `read_file` 直接失败——「项目」退化成列表里的一个标签；
- 第三场贴的图落在会话目录，第一场、第二场都读不到；
- 删掉会话时产出跟着没，或者反过来留下永远没人认领的孤儿文件。

另外还有「游离会话」：用户直接点「新对话」，不带 `workspaceId`。如果允许它存在，产出落在会话目录，项目页永远看不到这些对话，删会话就留下孤儿。

## 2. 候选与代价

| 问题 | 候选 | 好处 | 代价 |
|---|---|---|---|
| 同项目的多场会话 | A 每 session 一个子目录 | 天然隔离 | 跨会话读不到，项目名不副实 |
| | B 同项目共享 `workspaces/<wid>/`（定案） | 像 IDE 打开同一个项目 | 并发写同一块可变状态（由文件锁与指纹兜底，见 `doc/problems/同项目并发写文件怎么防`） |
| 默认工作区粒度 | A 每租户一个 | 省行 | 团队里 Bob 的私人附件会进所有成员的眼 |
| | B 每（租户, 用户）一个私有默认工作区（定案） | 隐私按人切 | 每人一行；要部分唯一索引 `(tenant_id, user_id) WHERE is_default` 防重 |
| 附件挂哪 | A 挂会话 | 实现简单 | 项目内不共享；删会话即失图 |
| | B 挂 workspace，可见性跟容器（定案） | 项目内共享、归属稳定 | 要迁移旧 path、改取图与模型读图 |
| 允许游离会话吗 | A 允许 | 兼容存量、少一步 | 产出归属混乱、删会话留孤儿、项目页看不到 |
| | B 不带项目就挂该成员默认项目；存量在下一场 run 归位（定案） | 产出有归属 | 需要默认工作区与归位逻辑 |
| 附件路径留几套 | A 新旧并存 | 老图还能看 | 双解析路径、双清理逻辑，漏改一处就是 404 或删不干净 |
| | B 只留 `workspaces/<wid>/.media/`，存量清掉、老 path 自然 404（定案） | 单一形态 | dev 期老图失效，要写 release note |

**裁定：B / B / B / B / B。**

## 3. 同族小裁定

| 小问题 | 裁定 | 代价 / 备注 |
|---|---|---|
| 附件可见性跟会话的 private/tenant 传导吗？ | 不传导，附件永远跟 workspace | 否则私人会话的图会因项目共享而泄露 |
| 默认工作区怎么防重复创建？ | 部分唯一索引 `one_default_workspace_per_user` | 闸放数据库不放进程；并发 `EnsureDefaultWorkspace` 不会造出两个默认项目 |
| 会话换项目怎么办？ | `PATCH /api/sessions/:id/workspace` 挂/解绑 | 解绑后下一场 run 归位到默认项目 |
| 项目重命名后旧路径怎么办？ | 目录随重命名移动，DB 存的是 workspace id 不是路径 | 避免路径成为第二个真源 |
