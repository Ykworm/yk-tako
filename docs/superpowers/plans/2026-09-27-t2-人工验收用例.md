## A 组：基础与流式（不依赖审批）

### A1 页面加载与静态挂点
1. 浏览器打开首页。
2. 看：输入框、右上角「新会话」「看板」按钮，状态显示「就绪」。

- **预期**：页面正常渲染，无 Console 报错；`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8765/` 输出 200。

### A2 SSE 逐事件（核心：不是跑完才一次性显示）
1. 发：`先查现在时间，再算 1234*5678，最后用一句话总结`
2. **盯着看**事件出现的节奏。

- **预期**：工具行（`调用 工具名` / `← 结果`）与正文**逐条、逐个出现**，不是整轮结束后一次性刷出；运行中「发送」变「停止」、状态「正在工作…」；结束后回「就绪」。
- **失败判定**：所有内容在结束瞬间一起出现 = SSE 没起流式作用。
- **备注**：模型具体调哪个工具不固定（查时间可能用 `get_current_time` 而非 bash，计算用 `calculate`），工具名与预想不同不影响判定；它觉得步骤够多时还会顺手建看板任务（TaskCreate/TaskUpdate 大量出现），同属正常行为。

### A3 看板面板
1. 发：`把「整理桌面」拆成 3 步记到任务看板，然后只做第一步`
2. 看右侧看板栏；点右上角看板按钮折叠/展开；把窗口拉窄到 <900px 再看。

- **预期**：看板出现任务行（与终端 REPL 的 📋 投影同款文本）；按钮能折叠/展开；窄窗变成抽屉式浮层（有遮罩，能关）。
- **备注**：模型偶尔偷懒不建表——重发一次再判，别把模型不听话记成 UI bug。

### A4 长任务 + 停止
1. 发：`用 bash 执行 for i in 1 2 3 4 5; do sleep 3; done，然后汇报完成`
2. 运行中（状态「正在工作…」）点「停止」。

- **预期**：出现「已停止。本轮作废，不会写入会话历史」；状态变「已停止」；发送按钮恢复；再发一条短消息能正常跑。
- **失败判定**：点停止后 UI 卡在「正在工作…」或后续无法再发。

### A5 新会话不继承上下文
1. 先跑 A2 或 A3，再点右上角「新会话」（运行中会弹确认框——确认会中止当前轮）。
2. 先问：`我刚才让你做了什么？`

- **预期**：聊天区清空重来；模型答不出上一会话的事；看板回到空态（「还没有任务」）；Network 里新一轮 `/api/chat` 的 `sessionId` 与之前不同（localStorage 里 `yktakoSession` 变了）。

## B 组：审批回路（T2 核心，两条路径都要走）

### B1 拒绝路径
1. 发：`用 bash 执行 rm -rf /tmp/yktako-ui-test`
2. 等审批卡片弹出，看卡片内容，点「拒绝」。

- **预期**：卡片显示 工具=`bash`、参数含 `rm -rf /tmp/yktako-ui-test`、说明来自 guard 规则；点拒绝后卡片消失、出现「已拒绝，模型会收到说明」；模型继续收尾（通常会说明未执行）。
3. 终端验证：`ls /tmp/yktako-ui-test` → **目录还在**（命令真没执行）。

### B2 批准路径
1. 同 B1 的请求再来一次；这次点「批准执行」。
2. 终端验证：`ls /tmp/yktako-ui-test` → 报 `No such file or directory`。
3. 重建靶子：`mkdir -p /tmp/yktako-ui-test && touch /tmp/yktako-ui-test/keep.txt`。

- **预期**：卡片按钮点击瞬间变灰（防连点）；批准后出现「已批准，继续执行」，命令真的执行，模型继续收尾。
- **失败判定**：批准了但目录还在（resume 断了）或点了没反应。

### B3 审批挂起时刷新页面（边界）
1. 触发一张审批卡，**先别点**，直接 F5 刷新。
2. 刷新后直接发一条普通消息（如 `你好`）。

- **预期**：审批卡不重现（这一轮随断流作废）；新消息能正常跑。若刷新后立刻发消息撞上 409「该会话已有一轮在跑」，等 1~2 秒重发（旧 run 正在收尾，属正常时序），仍不行才算失败。

### B4 审批挂起时点「停止」（边界）
1. 触发一张审批卡，点右上/底部「停止」。

- **预期**：卡片消失、状态「已停止」；随后发普通消息能正常跑；服务端终端无 panic。

## C 组：并发、隔离与接口边界

### C1 同会话并发 → 409（curl，不经浏览器）
```bash
SID=$(uuidgen)
curl -sN -X POST http://127.0.0.1:8765/api/chat -H 'Content-Type: application/json' \
  -d "{\"sessionId\":\"$SID\",\"message\":\"用 bash 执行 sleep 20 然后汇报\"}" >/dev/null &
sleep 3
curl -s -i -X POST http://127.0.0.1:8765/api/chat -H 'Content-Type: application/json' \
  -d "{\"sessionId\":\"$SID\",\"message\":\"第二句\"}" | head -5
kill %1
```
- **预期**：第二条返回 `409 Conflict`，body 含「该会话已有一轮在跑」；响应头里**没有** `text/event-stream`（冲突检查先于写 SSE header，这是《10》§3.1 照学 WeKnora 的顺序）。
- **说明**：浏览器同源多标签共享 localStorage 的 sessionId，在 UI 上表现为「另一个标签也在跑」——用第二个标签页发消息应看到 409 文案。

### C2 会话隔离（看板不串账）
1. 普通窗口跑一个记看板的任务（A3 的请求即可）。
2. 开**无痕窗口**（新 sessionId）跑一个不同的看板任务。

- **预期**：两边看板各自独立、互不出现对方的任务；聊天历史也互不可见。

### C3 运行中刷新（断线语义）
1. 跑 A4 的长任务，中途 F5。

- **预期**：刷新后无报错、状态「就绪」，可以正常发新消息；**没有**断线回放（刷新前的这轮内容不再出现，这是《10》§4.4 的冻结边界，属预期不是 bug）。

### C4 接口参数校验（curl）
```bash
curl -s -o /dev/null -w 'chat 缺字段: %{http_code}\n' -X POST http://127.0.0.1:8765/api/chat \
  -H 'Content-Type: application/json' -d '{"sessionId":"x"}'
curl -s -o /dev/null -w 'approval 非法 decision: %{http_code}\n' -X POST http://127.0.0.1:8765/api/approval \
  -H 'Content-Type: application/json' -d '{"sessionId":"x","requestId":"y","decision":"nope"}'
curl -s -o /dev/null -w 'approval 不存在 requestId: %{http_code}\n' -X POST http://127.0.0.1:8765/api/approval \
  -H 'Content-Type: application/json' -d '{"sessionId":"x","requestId":"y","decision":"approve"}'
```
- **预期**：依次 `400`、`400`、`404`（第三条 `x` 会话不存在也算 404）。

### C5 暗色适配（外观）
1. 系统外观切到深色（macOS：系统设置 → 外观），页面自动跟随（跟随系统，没有页内开关）。

- **预期**：正文/审批卡/看板对比度正常、不刺眼；无「白底黑字里夹一块亮霓虹」之类的断层。仅观感判定，不通过就描述具体哪块难看。

## 明确不用测 / 不要报的（《10》§5 范围冻结）

- token 级流式 delta（第一期只做整消息级）；
- 断线重连、事件回放、跨实例（进程内存，重启即丢）；
- 多用户/鉴权/RBAC（单用户、只绑 127.0.0.1）；
- 运行中插话（steer）；
- Wails 桌面壳；
- 上下文管理（#4，顺延中的下一层）。
